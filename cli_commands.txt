# --- gate_cage_ball: 插板截留往复小球 (任务书 4.1) ---
# 工业原型 = 直线振动送料轨上的插板阀。球沿轨道**匀速往复**(_ball_drive.py 的 BallShuttle 驱动,
# 撞到东西就换向), 不靠斜坡。终态自明: 成功=球在盒内持续来回撞, 失败=球从敞口滚出轨道。
# 两端不对称: 近端敞口(球唯一出入口, 闸板封的就是它), 远端实壁(撞上换向)。
# 三个正交旋钮: ball.speed 缩放全部时序 / entry_start_y 定球何时到门 / flat_end_y 定窗口多长。
# 基准难度 = 臂比球先到, 必须在槽口上方悬停约 0.9s 等球进来再下板。
#
# 小球标定 spike (tests/ball_roll_spike.py) 的结论已并入本设计: 零滚动阻力 + 零回弹
# => 球没有自发换向的手段, 故改为驱动式匀速往复。spike 仍可用于复核求解器行为。
#

# --- PBD 布料 spike (类别 1 的建模方案, 2026-08-17 新建) ---
# 诊断工具, 不是任务。结论写进 docs/develop/physics/cloth/pbd_cloth_spike_zh.md。
#
# 第一轮 (2026-08-17) 已定的两条, 不用重跑:
#   cost    : 每步 9ms, 与 particle_size 基本无关。比 FEM+IPC 的 660ms 便宜 73 倍,
#             所以 particle_size 按判据精度选即可, 不用为速度让步。
#             墙钟被建场景占满 (每个进程约 3.5-4 分钟), 优化每步没有意义。
#   contact : Genesis 1.2.1 上不再 segfault (1.1.0 上会), 撑到净空 0。
#             但手指把布推到桌面下方 2.5mm, 接触并不干净。
# 第一轮作废的三条 (仪器问题, 已修, 需重跑): settle / weld / speed —— 见下。
#
# 统一跑法 (推荐): 每格独立进程+超时, 最后打一张汇总表。
bash bash_scripts/tests/pbd_cloth_spike.sh                   # 全部七项
bash bash_scripts/tests/pbd_cloth_spike.sh fold              # 只跑唯一还能推翻方案的那项
bash bash_scripts/tests/pbd_cloth_spike.sh grip              # 第三轮: 先解决抓不住
SKIP_CONTACT=1 bash bash_scripts/tests/pbd_cloth_spike.sh         # 跳过可能崩的那项
# 可调: BACKEND / DRAG_SPEEDS / PINCH_QPOS / SETTLE_DROP_Z / PARTICLE_SIZES /
#       BENCH_STEPS / TIMEOUT_S / SKIP_CONTACT / OUTDIR
#
# 下面是等价的手动分解 (调试单项时用):
# 1) 静置基线 + **重力是否真的作用在布上**。必须从高处放手: 第一轮把布生成在了
#    平衡高度上, 全程零位移, 分不出「没事可做」和「根本没在仿真」。先看 gravity= 那项。
python -B -m tests.pbd_cloth_spike run.test=settle task.cloth.z=0.050 run.verbose=true 2>&1 | tee runs/cloth_settle.log
# 2) **当前的阻塞项**: 夹爪抓不住布 —— 2026-08-19 实测手抬 40mm 布只上来 16.4mm。
#    四种「让布跟着夹爪走」的方式, 同一次垂直提起上对比:
#      overwrite_graded 物理算完后从 Python 改坐标, 每个点按到中心的距离只听一部分 (原默认)
#      overwrite_rigid  同上, 但每个点完全听话
#      link_patch       fix_particles_to_link: 算物理之前就告诉求解器这些点跟着夹爪走
#                       (绳子任务一直用这个), 还会跟着一起转
#      link_single      同上, 但只绑最近的一个点 (SoftGym picker 的配置)
#    读 follow_ratio (接近 1 才算抓住) 和 worst_edge_strain (抓得越死材料拉伸越多)。
#    link_single 还要在 viewer 里确认布角不会绕着那一个点乱转。
bash bash_scripts/tests/pbd_cloth_spike.sh grip
#    或者手动单跑一种:
python -B -m tests.pbd_cloth_spike run.test=grip run.verbose=true task.grasp.attach_mode=link_patch 2>&1 | tee runs/grip_link_patch.log
# 3) 速度预算。第一轮扫到 0.008 全过、看门狗从未响 (阈值设成了 20mm, 而实测最大
#    位移 8.4mm), 所以「没炸」等于「没往危险的地方看」。现在扫过隧穿门槛 0.012,
#    看门狗改成「粒子位移 > 3 倍驱动端位移」才算发散。
python -B -m tests.pbd_cloth_spike -m run.test=speed run.drag_speed=0.002,0.008,0.016,0.032 2>&1 | tee runs/cloth_speed_sweep.log
# 4) 挤压 (新增): 在布上合拢手指。这是「夹爪穿模、布飞出去」最可能的机制,
#    而 contact 测不到它 —— 那一项是闭着手指往下降, 从没在布上合拢过。
#    参照量 particle_size/2 = 0.003 是单层布的半厚, 扫参跨过它。
python -B -m tests.pbd_cloth_spike -m run.test=pinch run.pinch_qpos=0.0005,0.001,0.002,0.004,0.006 2>&1 | tee runs/cloth_pinch_sweep.log
# 5) **最关键的一项**: 真正的对折动作 —— 把边提起、越过中线、放到另一半上、松手、静置,
#    然后量两层布有没有互相穿过去。这是唯一还能推翻 PBD 方案的问题:
