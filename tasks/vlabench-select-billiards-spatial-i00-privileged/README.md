## Task
VLABench's `select_billiards_spatial`: a Franka Panda arm at a table, instructed **"Please put the striped_14 in the right bottom pocket (the corner pocket near x = 0.52, y = -0.99)."** (a description of where the target is). One
frozen scene instance (VLABench's own episode configuration for the task, seed 0); the deliverable is one
replayable trajectory of joint-position control steps (`/app/output/trajectory.npz`, `(T, 9)`, T ≤ 4000), graded by
VLABench's own success check at its end.

## Difficulty
Privileged mode: the agent has every entity's pose and grasp and place points, VLABench's general skills (pick, place,
pull, press, …) as planning primitives, inverse kinematics, unlimited resets and self-replay. What remains hard is the
task's own reasoning (the instruction is a description of where the target is) and making the skills or a hand-written controller
succeed on this scene. The standard twin removes the privileged state.

## Reference solution
248 control steps on this instance (`solution/oracle.npy`), replayed by `solution/solve.sh`. Source:
VLABench's own expert (get_expert_skill_sequence) driving its general skills, recorded as control steps during PR #4's authoring; only the recorded steps were committed (PR #4 @ ad3c510, refs/pull/4/head). VLABench's experts are removed from the image. Re-verified by `scripts/vlabench/freeze.sh`: the
replay ends with the task's success at its last step.

## Verification
`tests/grade.py` in a separate sandbox without network: two replays in fresh processes from the verifier's own copy of
the instance (`tests/instance.json`); pass iff both end in the same state (`deterministic`) and the task succeeds at
the last action (VLABench's termination condition; actions after it make the trajectory invalid). Oracle: the replays
end in the live state (hash `b1c967d47764…`) and succeed. `nop`: no trajectory, reward 0; the instance is not solved at
the start (checked on every load).
