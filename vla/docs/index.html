2 · 差异与适配

TopoGym 与训练配置的差别，以及能否适配

机器人层面

TopoGym 的机器人与这种机器人的常用配置不同（Panda 参照 DROID，ALOHA 参照标准 ALOHA）。同一机器人上的所有模型都受影响；适配写一次，所有模型共用。
例：Panda 的夹爪安装角

模型层面

只与某个模型的训练机器人或输入约定有关，只影响这个模型；适配写在该模型的包装层或配置里。
例：GR00T 的 eef_9d 读法、X-VLA 的两臂布局

每行两个影响：直接用 是不做适配时的影响，适配后 是按表中方式适配后剩余的影响；已适配的项依据核对或实验，其余为预估。处理方式：已适配（vla/ 内已做）vla/ 可做 TopoGym 可改（本分支不改）无法适配。仿真画面与真实照片的外观差别所有模型都有，不列入表中。

4 · VLA 选择

接入了哪些模型，为什么

6 · 工作方式

两个进程，一条 TCP 连接

评测进程在 TopoGym 的 conda 环境里驱动 reset、step、录像和判定；每个模型在自己的 conda 环境里起服务，只回答"观测 → 动作块"。两侧只共享 vla/protocol.py（标准库 + numpy），传输用 multiprocessing.connection，JSON 头加数组原始字节，不用 pickle。

conda activate vla-pi05
python -m vla.models.serve --config vla/configs/models/panda_robotiq/pi05_droid_jointpos.yaml

conda activate topogym
python -m vla.gym.run_eval --config vla/configs/eval/buzz_wire_3d.yaml task.seeds=[0] task.sim_seconds=10

环境：bash vla/setup.sh <topogym|pi05|groot|molmoact2|xvla>。配置按机器人分目录，用 _base_ 继承，命令行 key=value 覆盖；端口在运行时指定（默认 8000）。使用说明见 vla/README.md，设计与变更记录见 vla/docs/IMPL_PLAN.md。

证据在评测机器的 runs/test_results/20260930_vla_*（不进 git）：第二批评测 20260930_vla_p5_*，调用核对 20260930_vla_round2_audit，eef_9d 实验 20260930_vla_groot_eef9d，夹爪实测 20260930_vla_round3_gripper，到位步数 20260930_vla_round2_reach。本页源文件：vla/docs/index.html。
