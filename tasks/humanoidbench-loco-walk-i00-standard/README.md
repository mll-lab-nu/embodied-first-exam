## Task
Standard mode (robot as a service, `eai-standard/2.1`) of `humanoidbench-loco-walk-i00-privileged`: the same
frozen instance and the same success rule. HumanoidBench runs in the `sim` sidecar
(`environment/docker-compose.yaml`, GPU on the sidecar for rendering), which holds the reward, judges the
episode, records it, replays it in a fresh simulator and renders the replay video; the verifier grades the
sidecar's record in a container of its own (`tests/Dockerfile`, no network).

Note: the head cameras see flat floor and the horizon (there is nothing else in the scene). `room_camera`
stands behind and above the start and looks down the course (`RCB_ROOM_CAMERA_POSE` in the compose file): the
robot stays in frame from x = 0 to 20 m.

## Difficulty
See `humanoidbench-loco-walk-i00-privileged`'s README; here the agent also has no state, no reward and no
simulator of its own, and 50 resets instead of unlimited ones: every try is a real episode on the one robot.

## Reference solution
None. Requiring one would cap the benchmark at what we can already solve, which systematically removes the
interesting tasks. What replaces it (docs/PROTOCOL.md §2.7): the floor above (doing nothing cannot pass), the
evidence that the task has a solution (`oracle_evidence` in task.toml), and a human reviewer.

## Verification
`success` = live success (the episode's return reached the pass mark) ∧ replay success ∧ deterministic (the
fresh replay ends in the live run's state), computed in the sidecar for the last episode (the one after the
last reset; earlier episodes are in `trajectory_live.f64` and `episode.jsonl`, not graded); `tests/grade.py`
reads `/data/final.json` and copies the evidence to `/logs/verifier/` (`replay.mp4`). No oracle; human review
in PR #9. `nop` scores 0.

Generated by `scripts/humanoidbench/gen_tasks.py` from `subset.toml`, `templates/standard/` and
`shared/standard/`.

## Details
| | |
|---|---|
| mode / sensors | standard: head-camera RGB + joint angles and velocities (HumanoidBench's own `image` and `proprio` sensors), a pelvis IMU and a camera fixed in the room; no root pose, no base velocity, no reward; 50 resets (a new episode from the frozen start each; only the last episode is graded) |
| action space | HumanoidBench's own: 19 normalised position targets, 50 Hz, sent in chunks |
| knobs (compose env) | `RCB_RESET_BUDGET` (50: HumanoidBench's standard configuration, docs/benchmarks/humanoidbench.md), `RCB_OBS_PROPRIO` (1), `RCB_OBS_IMU` (1), `RCB_OBS_ROOM_CAMERA` (1), `RCB_OBS_DEPTH` (0): the defaults are the standard configuration; a run that changes one (`RCB_RESET_BUDGET=0 harbor run ...`: one episode, no reset) is reported separately, and `episode.jsonl` records the `/spec` it ran under |
| agent API | `environment/rcb_client.py` (its docstring is the reference); `instruction.md` lists the endpoints |
| physics vs upstream | upstream's model (HumanoidBench cb11890) on MuJoCo 3.3.7, not the 3.1.6 upstream pins, whose convex collision reported wrong contacts; results on image 0.1.6 or earlier are other physics and are reported apart (docs/benchmarks/humanoidbench.md, Physics). |
