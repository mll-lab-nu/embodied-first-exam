本报告用到的术语

后面各页第一次出现这些词时不再展开。

Part 1
术语含义
oracle / planneroracle 是「已知全部真实状态、能给出正确动作序列」的脚本化求解器；planner 是它内部把任务拆成子目标和轨迹的部分。oracle 用来录制模仿学习数据，也用来证明任务可解。
不变量（invariant）一个任务真正要改变的量。它在正确动作前后取值不同，在走捷径的动作前后取值不变。每类任务的不变量类型固定（见 1.4 页）。
winding number（绕数）绳绕柱子转了几圈，带正负号表示方向。routing 类任务的不变量。
交叉数与上下符号两根线在俯视投影下相交几次；每处交叉记录哪根在上、哪根在下。entangle 类任务的不变量。
连通分量数 / S–T 可达把物体能到达的空间看成一张图，数它被分成几块；或者问起点 S 能否到达终点 T。connectivity 类任务的不变量。
gateway（通道）改变不变量的唯一路径，例如柱顶、C 形环的开口。通道唯一，捷径就不存在。
contrast pair（对照轨迹）一条终点位置与成功轨迹几乎相同、但不变量没有改变的轨迹。用来证明判定函数不是靠位置阈值判成功。
术语含义
FEM+IPC有限元 + 增量势能接触：把绳当作有体积的弹性体求解，接触靠势能函数保证不穿透。绳类物体的求解器。
PBD基于位置的动力学：把布看成粒子网，每步直接修正粒子位置满足约束。速度快，但没有法向阻挡，布可能沉进桌面。布类物体的求解器。
IK（逆运动学）给定末端要到的位置和姿态，反算七个关节角。IK 跟踪误差指末端实际到达点与目标点的距离。
三机位每个 demo 固定录三个视角：oblique（斜上方第三人称）、front（机械臂正前方）、wrist（装在手腕上的相机，与策略观测一致）。
随机种子（seed）与实例seed 是一个整数；同一个 seed 总生成同一个场景实例，不同 seed 生成不同实例。
难度档easy / default / hard 三档。本方案里每档对应一组采样分布，而非一组固定参数值。
拒绝采样采样一组参数后先做几何可行性校验，不通过就丢弃并重新采样。
稳定性 sweep对同一任务遍历多个 seed × 多个难度档批量运行，统计崩溃数与失败数的脚本（stability_sweep.sh）。

1.4

目标 3：planner / oracle 的分层结构与判定契约

oracle 的写法受两条约束：四类任务各自的判定契约（判定函数必须读出的不变量），以及三层的 planner 结构。

Part 1
类别不变量的类型允许的不变量名必须在判定中声明的前提物理层复核（几何读数之外再做一次物理验证）
C1 deformation多个浮点指标同时满足守恒/结构指标（层数、材料铺展长度）+ 形态指标（高度场方差、覆盖 IoU）标注该类没有整数拓扑不变量无单独复核，指标本身包含物理量
C2 routing整数或整数元组winding_number / linking_number / threading_count绕数的闭合方式、参考轴、通道（gateway）释放测试、张力传递测试或拖拽约束测试
C3 entangle带符号的交叉序列crossing_number / signed_crossing_sequence投影方向、固定的边界条件（悬挂端固定）把两根线向两边拉开，看是否真的分离
C4 connectivity整数（连通分量数）或布尔（S–T 可达）component_count / st_reachable连通性定义在哪个空间上：物体的自由空间，或零件连接图；随机化必须注册晃动测试、贯穿到底测试、S–T 弹珠测试、提起测试
任务规划层（task planner）
输入当前任务状态，输出一串离散子目标；每个子目标带目标位姿、与障碍的间隙、预期接触对象、成功谓词、安全谓词。长距离动作按规则拆成短段：单段距离和方向变化不超过阈值，靠近障碍时自动加大间隙。
运动原语层 + 安全监视层
把子目标转成 Franka 的末端轨迹，执行前先检查逆运动学是否可达、是否会穿过障碍；提供抓取、抬起、拖拽、放置、释放等原语。执行中监视跟随误差、目标误差、最小间隙、接触粒子数，出现高风险状态时软中止并保存结构化记录，避免把物理引擎拖到崩溃。
现状：11 个任务的 oracle 路点均由配置或实时状态推导，没有手写的绝对坐标；例外是 bar_through_hole 的 primitive.*_z 与 gate_cage_ball 的 motion.*_z，它们是手工推导的绝对高度，变体方案要求改为由布局推导。每个任务还必须有可执行的对照轨迹（contrast pair），缺少的任务不进入 benchmark 产物。

2.1

rope_winding · 绳子绕柱（0 → 2 圈）

绳用 FEM+IPC 求解器模拟。机械臂抓住绳端的插头后，手腕旋转 90° 使绳头朝下，沿螺旋上升的轨迹把绳绕柱两圈，最后把插头放到 C 点。成功判定读取绕柱圈数（winding number）；改变圈数的唯一通道（gateway）是柱顶——绳只能从柱顶越过去，不能从柱身穿过。

ring_transfer · 绳圈从柱 A 转移到柱 B

场景是两根顶部带挡头的柱子和一个闭合的弹性绳圈。主 oracle 叫 carry（捏取 + 搬运套索）：两根手指从环内钩开一段、借 A 柱把环撑开成可套的形状，再整体搬到 B 柱套入。成功判定读取每根柱子被环绕的圈数。

bar_through_hole · 横杆穿过孔（刚体）

纯刚体场景：一块竖直面板上开矩形孔，一根圆柱横杆，三个托架（cradle）。oracle 的动作是对准孔、插入、落座到远端托架。对照轨迹 bypass 绕过面板直接把横杆放到远端托架：终点位置几乎相同，但穿孔次数（threading count）没有变，判定为失败。

2.4

swap_crossing_sign · 交换两根线的上下关系

两根线缆的悬挂端固定在桌上，中间有一处交叉。oracle 分两步：先把上面那根移开，再把另一根压过去。任务前后交叉数都是 1，只有「谁在上面」（交叉符号）翻转了，因此判定必须同时记录交叉数和上下符号。

3.1

现状：随机化入口已有，任务未登记

方案回答三个问题：每个任务哪些参数可以随种子变化、场景几何简单时怎样让不同种子产生实质不同的实例、难度如何定义为分布并验证。

Part 3
项现状
随机化入口函数layout_randomization.py::randomize_task_cfg(cfg, task_id, seed, difficulty)：复制任务配置，按注册表对登记的参数施加有界扰动，未登记的任务原样返回。现有的四种扰动指令全是连续量的抖动
已登记的任务untangle / cable_routing / stacked_plate / peeling。本方案的 11 个任务均未登记
难度的现有实现_DIFFICULTY_SCALE = {easy 0.5, default 1.0, hard 1.8}：所有扰动半宽乘同一个倍率
随机种子对场景的作用只有 swap_crossing_sign 的 seed 进入场景生成（决定交叉符号）；其余 10 个任务的 seed 只是数据记录里的身份字段，不影响场景
离线几何校验6 个任务有 tests/check_*_geometry.py；linkbar 有 validate()；diverter 有 check_pivot_clearance()；bar_through_hole 没有校验器
oracle 对配置的依赖路点均由配置或实时状态推导；例外是 bar_through_hole 的 primitive.*_z、gate_cage_ball 的 motion.*_z（手工推导的绝对高度）
结论：随机化入口函数和测量脚本（stability_sweep.sh）都已存在，缺的是 11 个任务的注册表条目、三种新的扰动指令（离散选择、派生量重新计算、可行性校验），以及运行配置里的 randomize_layout / difficulty 键。
3.2

通用规则：参数分四类 · 从种子到实例 · 难度是分布

场景几何简单时，实例之间的差异主要来自 A 类轴，B 类轴提供连续覆盖。

Part 3
类别定义采样方式
A 实例轴离散取值，改变正确动作本身（绕哪根柱、转向哪一侧、绕几圈、交叉符号）按给定概率从有限个取值里选一个（Categorical 分布）
B 布局轴连续的几何量（位置、角度、尺寸），oracle 读取后自适应，改变动作的位置与幅度有界连续分布
C 派生量由 A、B 决定、必须随之重新计算的量（绳长、步数、跟随高度）重新计算，不采样
D 固定量已有实测失败记录或受求解器约束的参数（粒径、接触距离阈值 d_hat、步长、摩擦、子步数）不变
每个 episode 的采样流程
  1. 用 SeedSequence(seed) 为每条轴派生一个独立的随机数流，流的编号由轴名的哈希决定，因此新增一条轴不会改变已有轴在同一 seed 下的取值
  2. 先采样 A 类，再采样 B 类，再重新计算 C 类
  3. 调用该任务的可行性校验函数；不通过则整组重新采样，最多 20 次，超过则报错并记录该难度档的拒绝率
  4. 采样结果写入 TaskVariant.parameters；数据文件的 setup 分组已有 difficulty 字段
难度定义为分布
难度档 d ∈ {easy, default, hard} 是一个映射：把每条轴 a 映射到一个分布 Pd(a)。一个 episode 由 (d, seed) 决定：seed 决定从 Pd 里抽到哪个样本。B 类轴用截断均匀分布 U[c − wd, c + wd]（在中心 c 两侧各 wd 的区间内等概率取值），难度改变半宽 wd 和中心 cd；A 类轴用 Categorical(pd)，难度改变各取值的概率。约束：easy 的取值范围包含于 default、default 包含于 hard（或者某个「裕度统计量」的期望随难度单调，例如期望间隙递减）；难度不写成固定取值表；范围来自物理量程，不从基线分数反推。现有的 _DIFFICULTY_SCALE 是这个定义的特例（中心不变、半宽乘倍率）。
新增的扰动指令用途使用任务
_ScalarJitter(path, lo_d, hi_d)单个标量参数的截断均匀采样，上下界按难度声明多数任务
_ChoiceJitter(path, choices, p_d)离散实例轴diverter / linkbar / rope_winding / ring_transfer / 布料的材料方向
_DerivedSolve(fn)采样后调用任务模块的函数重新计算 C 类参数rope_winding 的绳弧角度、bar_through_hole 的托架位置、ring_transfer 的柱对朝向
_Validate(fn, max_retry)采样后调用可行性校验，失败则重新采样全部
原则：每个任务至少一条 A 类轴，使脚本化策略（固定方向、选最近目标、固定延时）的期望成功率被固定在随机水平；B 类轴使策略无法记忆绝对坐标。视觉参数（颜色、纹理 seed）单独随机化，不在本方案内。

一条槽道到中间分成左右两岔，分岔口有一块可转的拨板，板上连一根带旋钮的拨杆；一条岔是死路。球从入口滚进来。指令说「送球到目标」，目标在活路那边。任务：看指令或看哪条路通，转拨板，让球滚过去。
参数拧了之后画面怎么变
dead_end_side（死路侧）死路在左还是右。
init_sealed_side（初始封侧）拨板出生时封着左还是右。两者组合起来，一半场景中拨板已经封住死路，正确动作是不转，直接放球。
target_pad.enabled（目标垫）活路出口有没有一块目标垫。有垫：看画面就知道该去哪；没垫：只能靠指令。
branch.angle_deg（岔角）两条岔道分开的角度（25–35°）。分得开，球容易落座；分得窄，容易卡。
lever.radius（拨杆长度）拨杆长短，手画的圆弧半径随之变。
fork_origin_x（分岔口位置）分岔口前后挪。
ball.speed / release_x球快慢、起点。
easy死路左右各半、初始封侧各半（所以一半场景不用转）；全部有目标垫；岔角 28–32°。
default三成场景没有目标垫（必须读指令），岔角 26–34°，分岔口挪 1 cm。
hard七成场景没有目标垫，岔角 24–36°，拨杆长短 ±8 mm，分岔口挪 1.5 cm。
3.10

linkbar_merge_components · 连杆合并两个部件

类别 connectivity。左：每个参数单独变化时的效果；右：三档难度下的典型场景。

Part 3
基准场景
中间一个转轴上装着一根横梁，梁末端有销钉；转轴左右各有一个插口：一个属于本体 A（转轴所在），一个属于小车 B（在轨道上）。两个插口长得一模一样。任务：转梁把销钉插进 B 的插口，A 和 B 连成一体。
参数拧了之后画面怎么变
B1 所在侧B 的插口在梁的左边还是右边（A 的在另一边）。
b1_angle、a2_angle（插口角度）两个插口各自离梁初始方向多少度（35–75°）。关键是两者之差：如果 B 的插口在 +40°、A 的在 −70°，「转向最近的那个」恰好对；如果 B 在 +70°、A 在 −40°，就近就错了。两者差越小，靠就近猜对的概率越接近一半。
init_angle（梁初始角）梁初始不正对前方，偏 ±15°，两个插口跟着一起偏。
easy两个插口一近一远，差至少 20°（比如 B 在 65°、A 在 40°）。
default两个角度独立随机，差可能大可能小。
hard两个插口离梁几乎一样远（差 ≤ 10°），看远近猜不出来，只能看归属。

cloth_fold · 布对折

类别 deformation。左：每个参数单独变化时的效果；右：三档难度下的典型场景。

Part 3
基准场景
一块 24×24 cm 方布平铺在桌上，中心略偏右。任务：捏一个角拎起来，沿弧线走过去，放在对角上，布对折成三角。
参数拧了之后画面怎么变
抓取角序号捏左上 / 右上 / 左下 / 右下哪个角，折的方向随之变（现在只实现了一个角，要补代码）。
cloth.center（布位置）布在桌上挪位置。挪太远，手臂够不到抓取角或落点。
grasp.inset（抓取内缩）从角尖往里多少捏。往里捏多了，角尖会耷拉，折出来不整齐。
fold_slack（弧线松紧）手拎着走的弧线半径比布的对角线略短（0.98）就是松着折，等于 1 就是绷着折。
布的大小、网格、粒径不动（33×33 是唯一实测不出错的组合）。布不能转角度（网格生成器只做轴对齐，要改代码）。
easy四个角随机，布挪 1 cm 以内，从角尖捏，弧线绷紧（0.97–0.99）。
default布挪 2 cm，可能从角往里 1 cm 捏，弧线松紧 0.95–1.0。
hard布挪 3 cm（接近可达边缘），往里 2 cm 捏，弧线可松到 0.93（布拖着走）。

cloth_unpleat · 展开褶皱

类别 deformation。左：每个参数单独变化时的效果；右：三档难度下的典型场景。

Part 3
基准场景
一条 12 cm 宽、26 cm 长的布带，中段叠了一个 Z 形褶（三层叠在一起），沿桌子前后方向铺。任务：捏住自由端，沿布带方向拉，把褶拉平。
参数拧了之后画面怎么变
material_axis（材料方向）布带沿前后铺还是左右铺（转 90°）。
cloth.center布带挪位置。

crest_height（褶高）褶隆起多高。

default褶宽 26–38 mm，隆起高度 ±4 mm，挪 2 cm。
hard褶宽 24–30 mm（小褶，拉平和压塌的判据只差一点），从布边往里 8 mm 或更靠里捏。

cloth_unroll · 展开卷布

类别 deformation。左：每个参数单独变化时的效果；右：三档难度下的典型场景。

Part 3
基准场景
一个小支架横着一根杆，一条布带卷在杆上 1.5 圈，尾巴垂下来搭在桌上。任务：捏住桌上的布带末端，把布拉出来展平。
参数拧了之后画面怎么变
material_axis支架和拉的方向转 90°。
cloth.center（杆的位置）支架挪位置，但布全展开后末端不能超出桌面工作区。

bar_height（杆高）杆离桌面多高，卷不能碰桌面。
easy卷 1.25–1.5 圈，支架挪 1 cm 以内，杆高 ±3 mm。
default卷 1–1.75 圈，前后 / 左右各半，支架挪 2 cm。
hard卷 1.25–1.75 圈为主（拉的距离最长），支架挪 3 cm（接近工作区边缘），杆高 ±8 mm。
