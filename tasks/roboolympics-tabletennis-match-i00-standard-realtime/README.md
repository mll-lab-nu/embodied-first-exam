## Task
Robot table tennis in a continuous world slowed by a factor S (MuJoCo Franka Panda + paddle, DeepMind ball and table model, recorded real serves), seen only through two cameras of four frames each; one game to 5 points (lead by 2 from 4:4, at 6:6 the next point wins); format match: you against a scripted opponent (level 1-4) that serves every point, format duel: two players and a neutral serve machine, the receiver changing every point; format `match` (seats A),
action level `high`, program play. Generated by `tools/generate.py` from
`sports/tabletennis/sport.toml` (RoboOlympics task `tabletennis-match-wallclock-program-standard`, exported with `--upstream`: tools/upstream.toml); do not edit by hand.

Deviations from the rulebook:

- D1 (ITTF 2.11, 2.12): one game to 5 points (from 4:4 a lead of 2 is needed, at 6:6 the next point wins: 7 points at most) instead of a best-of-games match with games to 11
- D2 (ITTF 2.6, 2.13): the robots cannot toss the ball: format match - the opponent serves every point with recorded real serves and you always receive; format duel - a neutral machine serves recorded real serves and the receiver changes every point (as under the expedite system, 2.13.3, 2.15.3)
- D3 (ITTF 2.5.7): only the blade can strike the ball: the ball touching the handle or arm loses the point
- D4 (ITTF 2.10.1.9-2.10.1.11): a robot has no free hand: any contact of the arm or paddle with the table, net or floor loses the point
- D5 (ITTF 2.10.1.7): any double hit loses the point, deliberate or not
- D6 (ITTF 2.15.4): the expedite rule applies from the first point: the receiver's 13th good return in a rally wins it the point (this bounds every rally)
- D7 (ITTF 2.9.1.1 (let)): a serve that touches the net or is irregular is a let; duel: faults by both players at the same instant are a let; the robot that is not receiving is transparent to the serve until it bounces on the receiver's half (the recorded serves were made for an empty serving end)
- D8 (- (cost limit, not from the rulebook)): if 40 points (lets included) are played the game ends: the player ahead wins; at a level score the player who won the last point (never reached in practice)

## Difficulty
Frozen instance (no run-time variables): seed 101 (it places the world and draws the execution scatter), opponent level 1, slowdown S = 10 (the world runs at 1/S of real speed). The RoboOlympics task `tabletennis-match-wallclock-program-standard` sets these at run time; this export fixes one official configuration, in which the reference player wins.

## Reference solution
`solution/solve.sh` runs the sport's reference player (`solution/builtin_players.py`) through the core's client
(`solution/ro_client.py`): camera images and `/spec` only.

## Verification
The `sim` service (the v0.2 core, `environment/sim/core/`) records the match (`episode.jsonl`) and a fresh process
replays it (state hash); the verifier (`tests/grade.py` = `core/grading.py`, no network) writes the common reward
fields (`success`, `valid_trial`, `deterministic`, `<seat>_won`, ...) and the sport's fields (`tests/sport_grade.py`).
