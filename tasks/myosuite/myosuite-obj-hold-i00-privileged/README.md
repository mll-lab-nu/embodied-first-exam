## Task
MyoSuite `myoHandObjHoldFixed-v0` (MyoHand, a musculoskeletal model of a human forearm and hand, 39 muscles): Hold the object at the goal: its centre within 0.010 m of the goal site for 50 consecutive control steps (1.0 s). Failure (the episode ends): the object more than 0.30 m from the goal (dropped). The object starts resting in the hand and falls if the hand does not grip it.
A small object rests in the palm of the upturned hand; the goal site is right above it. The deliverable is one replayable trajectory of actuator commands (`/app/output/trajectory.npz`, `(T, 39)`, one row per 20 ms control step).

## Difficulty
First-pass rating: medium. The action is muscle-level (39 muscles, each only pulling, several crossing more than one joint, with activation delays): the agent has to build its own joint control from muscle excitations. MyoSuite's goal has to hold for 1.0 s, so passing through the goal does not count.

## Reference solution
MyoSuite's own NPG baseline policy for `myoHandObjHoldFixed-v0` (`myosuite/agents/baslines_NPG/`, shipped in the MyoSuite wheel and removed from the image), rolled out from the frozen instance and cut at the first success: `solution/oracle.npy`, 57 rows (float32-exact, so the standard twin's client executes the same rows), success after 57 control steps. Replayed and saved by `solution/solve.sh`; re-checked by `scripts/myosuite/make_facts.py --oracles` (two fresh sessions, same final state).

## Verification
`tests/grade.py` in a separate sandbox without network: two replays of `/app/output/trajectory.npz`, each in a fresh process, from the verifier's own copy of the instance (`tests/instance.npz`; the rebuilt start state is checked against its recorded hash); pass iff both episodes end in success (the goal held 50 control steps) in the same state (`deterministic`). `nop`: no trajectory, reward 0.

### Change Log
- 2026-10-10 (review round 3, board 0067): `tests/grade.py` only. A byte that is not valid UTF-8 in the session log
  the agent's tools write (`/app/output/rcb_session_log.jsonl`, read only for the self-reported `agent_*` cost fields)
  stopped the grader before it wrote a reward, so the trial had no verdict; the log is now read tolerantly and can no
  longer decide anything. A trial whose log is valid is graded as before; the pass rule is unchanged.
- 2026-10-10 (review round 3, board 0067): `tests/grade.py`, whose failure a 0 is. The width of the rows is checked
  against the instance's actuators before any replay (a file that is no trajectory for this instance is
  `bad_trajectory`, as before). After that check a replay process that gives no result (out of time, killed for
  memory, not started) is `replay_failed` with `grader_error = 1` and `infra_error = 1`; it was booked as the agent's
  `bad_trajectory`. Every `reward.json` now carries `infra_error` (1 next to every `grader_error`, so also when the
  verifier's host does not rebuild the frozen instance). The pass rule is unchanged; a trial graded `bad_trajectory`
  before this date whose rows had the right shape was an infrastructure failure.
