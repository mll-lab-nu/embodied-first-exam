# Oracle 开发专用工具：看清接触、局部重试和直接操控

日期：2026-10-02。本文保留原始需求背景。首版已经实现，实际接口与能力边界见 [calibration_tools README](../../../topogym/planning/calibration_tools/README.md)。目标是让参考策略开发者使用比正式模型更多的诊断与规划能力，同时保留正式任务的原始场景、动作和评分流程。

具体接口、集中目录、权限隔离与文件改动清单已整理到 [calibration_tools 工程计划](calibration_tools_engineering_plan_zh.md)。以下保留需求背景，实施以该计划为准。

后续各任务的实际反馈、共性工具缺口与环境请求集中维护在 [Oracle 工具与环境支持需求汇总](oracle_tooling_support_zh.md)，首条为 Interlocked Claws。该汇总区分来源发现、现有覆盖与待验收建议。

可以提供直接移动物体、抓持试验和参数微调。推荐把这些能力放在**独立的开发进程和工具目录**，而不是给正式 `run_trials` 添加一个可以打开的特殊权限开关。

## 1. 先补哪些能力

| 问题 | 建议工具 | 对写 oracle 的帮助 |
| --- | --- | --- |
| RGB 太慢，关掉后只能猜哪里卡住 | 单路近景、按阶段／异常取帧；显示碰撞网格、接触对、力方向、实际与目标夹爪开度。只在抓取失败、跟踪误差突增、接触变化时保存少量关键帧。 | 直接看到手指被哪个零件顶开、哪条边卡住；不用全程四路录像才能看一次问题。 |
| 每次修改都要重跑前面成功的步骤 | 在抓取前、提起后、转弯前建立阶段检查点，支持退回、逐控制步推进和局部重试。 | 路口有问题时只调路口；最终再从 home 连续跑一遍。 |
| 原生物理调用卡住，整个交互都无响应 | 独立 supervisor 看心跳和每步耗时；正常停止在 tick／动作边界生效，超时后停止本次拥有的 worker，保留最后已提交的状态与动作。 | 卡住的 worker 不拖住操作者；无需等它正常返回才能安排下一次试验。 |
| 不知道是几何不通，还是机械臂没走对 | 开发专用物体位姿／相对位姿操控、轨迹扫掠、距离和碰撞检查；先固定一件，直接扫另一件。 | 快速找出“物体怎样动能出去”，再把路线映射到夹爪和双臂。Keyhole 本次已经用这个方法找到候选路线。 |
| 抓姿和关节分支反复试错 | 显示候选夹爪，批量 IK／FK、关节余量、手指／腕部相机／双臂／桌面碰撞检查，按净空筛选。 | 在跑长物理过程前排除明显不可行抓姿。 |
| 微调建模后不知道改善在哪里 | 参数化生成预览、前后几何差、关键截面、通路净空报告；保留版本化参数补丁。 | 例如比较入口宽度增加 1 mm 是否增加了夹爪净空，而不是凭截图猜。 |

近景与碰撞叠加图属于诊断视图，不能伪装成正式相机原帧。正式证据仍使用 Nyx + compact_lab 和共享 `RecordingSession`。阶段截图／按需渲染需要补调度支持，目前不能假定只改一个开关就已具备。

## 2. 利用现有能力，不重复造执行器

仓库已有可以复用的基础：

- [World 状态](../../../topogym/world/genesis_world.py)包含物体状态、接触 link、力和穿透；[抓持管理](../../../topogym/world/physics/grasp_manager.py)保存左右手阶段及事件。先给这些数据补名称、几何定位和可读摘要。要绘制精确接触点，需进一步核对后端是否提供接触位置，不能把实体质心当作真实接触点。
- [Env 回溯](../../../topogym/simulator/env.py)已有同 episode 状态恢复。`history_storage="segment"` 只在初态和段起点保存完整检查点，`memory` 才保留更多可恢复状态；应按任务需要选择，不能让长任务无限堆内存。
- [SegmentRunner](../../../topogym/simulator/rollout_simulation/segment.py)管理段和执行记录。正在执行的段不能直接 rewind，开发工具先停止／结束当前段，再回溯。
- [Keyhole IK 与网格检查](../../../topogym/planning/cast_keyhole/kinematics.py)可作为第一个工具适配对象，后续再抽出跨任务公共部分。

还需补两个容易遗漏的地方：世界回溯后，策略的阶段、路点索引、积分误差和随机数状态也要恢复；Python generator 本身不是完整可移植检查点。建议后续复杂 policy 把这些变量显式存成可序列化状态。

当前原生物理 checkpoint 是**进程内、当前建场专用**。杀掉 worker 后不能直接把它当作跨进程恢复文件。第一版可靠恢复方案是重建同一冻结实例，回放已提交动作前缀；跨进程精确 checkpoint 另行实现和验证。

## 3. 怎样处理 RGB 与单步卡死

第一版优先做“单路相机 + 阶段关键帧 + 失败前后的短窗口”，通常比每一步保存四路 RGB 更有价值。也可在无 RGB 的物理调试中保存所需数值状态，失败后另开渲染进程做回放／重渲染；应标出来源 tick 和实际状态身份，不能插帧掩盖接触变化。软体必须有完整节点／形变数据，只有质心无法重建画面。

重渲染不一定更省总计算，但能把画面生成从每次控制循环移走，让开发者更快看到失败位置。直接关闭 RGB 是否仍有其他昂贵的状态记录，也需要分项计时确认。

单步中止要分两种：

- **正常暂停**：在原生 `scene.step()` 返回后的边界检查停止请求，保存一致状态。每次只提交有界小段，避免一次工具调用等完整 oracle 结束。
- **卡在原生调用内部**：Python 的停止标志不能保证中断 C++／CUDA kernel。由另一个进程判断超时、结束本次 worker；不保证立即终止已经挂起的 GPU 内核，也不能承诺恢复那一个尚未提交的半步。保留上一个已提交边界，必要时重启 worker 和重建场景。

需要区分首次编译、建场、普通物理步、渲染各自的超时预算，避免把第一次编译当卡死。supervisor 不进入物理子进程的锁，心跳同时报告当前阶段、已提交 tick 和调用耗时。只处理本次拥有的进程，不重启整台机器或影响其他成员作业；CPU 只监控，系统内存达到 90% 停止本轮相关 worker。

## 4. 直接移动物体和微调模型怎么开放

建议开发接口按以下语义提供；这些名称是拟议接口，不是现成 API：

```text
inspect(near="right_gripper", contacts=True)
checkpoint("before_turn") / restore("before_turn")
step_until(event="contact_changed", max_control_steps=20)
set_object_pose("keyhole_silver", pose=...)       # 暂停中的探索场景
sweep_object("keyhole_silver", poses=...)        # 返回碰撞、最小间隙、失败姿态
preview_geometry(parameters=...)                 # 新版本预览，不覆盖当前冻结实例
```

直接移动／临时固定物体，甚至临时模拟已抓持状态，可以用于**探查路线和抓姿**。但需要记录操作并标为探索运行：改变位姿时明确速度处理，清理不再有效的抓持约束／缓存，避免画面更新了而碰撞或历史仍留在旧位置。最终证明要重新从原初态出发，只通过真实机器人动作完成；探索轨迹可作为规划输入，不能当作已经执行成功的轨迹。

微调模型也应走几何生成器：输出新素材、更新碰撞和质量惯量，产生新的资源哈希与实例版本，再重建场景。不要只改视觉网格；已编译的碰撞形状不一定支持安全热修改。保留差异和回退路径，旧 oracle、IK 缓存及成功证据需要重新匹配身份。本次用户已确认的 Keyhole 场景不在这份工具建议中自动改变。

## 5. 与正式评测隔离及最小实施顺序

按最新目录要求，拟议实现统一放在 `topogym/planning/calibration_tools/`，包括开发 API、supervisor、worker 和 `python -m` 入口，不另建 `dev_session.py` 或 `planning/devtools/`。开发 supervisor 作为可信管理方持有诊断／操控能力，policy 仍只接收观测并返回动作；目录外的打包、隔离检查和必要共享扩展见上述工程计划。

当前 [.dockerignore](../../../.dockerignore) 和 [镜像清理](../../../images/topogym/prune.py)已排除 planning；继续保持开发工具、私有路点和 oracle 不进入模型任务镜像或 RPC。再补镜像内容／导入检查，确认 standard 和 privileged 的模型 agent 都不能访问这些额外开发能力。privileged 原本已有的状态读取和 rewind 仍按现有合同提供，不因此增加直接改物体接口。

探索日志放 `runs/oracle_dev/<run-id>/`，记录 `exploration` 身份、所有直接操控和几何补丁。正式验证另建 run，绑定冻结实例，拒绝把含开发操控的运行标成完整机器人成功。这样的区分让直接移动物体成为可放心使用的调试手段。

建议实施顺序：先做**接触摘要＋单路关键帧＋worker 超时保护**，再做**阶段回溯和策略状态恢复**，最后整合**物体扫掠、抓姿筛选与建模预览**。最小工具可按半天到一天估计；做成多任务复用工作台约 1–3 天，跨进程精确恢复和原生 GPU 挂死恢复不包含在这个初版估计里。
