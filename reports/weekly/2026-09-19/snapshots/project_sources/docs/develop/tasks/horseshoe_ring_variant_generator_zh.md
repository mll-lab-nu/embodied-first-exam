# Horseshoe Ring：用于实例生成的两层随机机制（v2）

本模块服务于后续数据集流水线：先生成可保存、可恢复的任务实例，再用同一实例进行机器人规划和物理验收。视频是可选输出；本轮不创建数据集或 H5。

当前三个家族各有一个完整重力执行通过的代表，已开放围绕各自代表的条件采样。
放行依赖对每个具体实例的验收；并未宣称所有候选参数都必然执行成功。

动作对照：[cam_high](../../../demos/horseshoe_ring/cam_high/2026-09-19_families_v2_approach_comparison_cam_high.mp4)、
[cam_low](../../../demos/horseshoe_ring/cam_low/2026-09-19_families_v2_approach_comparison_cam_low.mp4)。
每段 9.8 秒，从左到右 F1/F2/F3，来自各自完整成功执行中的接近阶段，1 倍速，短段结束后保持末帧。
相机相同、目标环统一显示为银色；保留各实例的真实几何与状态。它们是局部动作对照，不是三个完整视频 demo。

## 固定设计与连续参数

选择预先设计的离散 `family_id`，不随机发明家族。v2 保留双臂折合、右手支撑、左手取环的流程，区别放在左手接近圆环的空间通道：

| 家族 | 固定动作特征 | 中间 TCP 目标，机器人安装坐标 / m |
| --- | --- | --- |
| F1 | 从高处下降接近圆环 | (-0.08, 0.06, 0.44) |
| F2 | 经正 Y 方向的外侧接近 | (-0.22, 0.20, 0.25) |
| F3 | 先后撤到负 Y 通道，再接近 | (-0.10, -0.20, 0.22) |

这些是**新的物理动作家族**，不沿用旧运动学视频的资格。旧 F2/F3 去除整体位姿、尺度和时间变化后，路线 P95 距离仅为 38.0 / 27.9 mm，未通过 50 mm 门槛。v2 的家族指纹明确取从安全 home 进入设计通道点的阶段；之后的腕部对齐允许按实测圆环姿态重规划。旧试验中两阶段共用一个名称，按已保存计划的第一段帧数恢复边界，不手工裁剪曲线。

在真实执行状态上去掉初始位姿、尺度并等弧长采样后，F1/F2、F1/F3、F2/F3 的通道 P95 差异分别为 **220.2、203.8、223.5 mm**；超过 50 mm 的路径比例分别约 79%、79%、83%，全部通过 50 mm / 20% 门槛。已检查同视角关键帧；高位视角能看清后撤方向，低位视角补充高位/外侧的高度差。新候选还须与本族参考通道的 P95 差异小于 50 mm，并保持与另外两族的区分。

固定形状库当前只开放 `classic_circle`。它是五个自由刚体的已设计经典原型，各家族使用它以便比较动作。内凹、宽 U 形、椭圆环的已有几何见证仍保留，但未完成机器人抓点和重力配对，不能混入已验证物理样本库。固定原型无需每条数据重新反推 CAD。

家族内以 [paired_anchors.json](../../../assets/tasks/horseshoe_ring/family_space_v2/paired_anchors.json) 中本族的物理成功实例为中心。当前候选半宽为：统一尺寸比例 **±0.002**、初始 XY 各 **±0.75 mm**、yaw **±0.15°**、通道中间点 Y **±1 mm**；超出前期探索总界限时收窄该条件区间，再均匀取样，不能跨族合并成一只参数盒。F1/F2 的中心尺寸比例分别为 1.0097214 / 1.0092017，F3 为 1.0。目标环有银色、黄铜色、深钢色三个预设。颜色只改变渲染，不改变摩擦、密度或碰撞体。

具体条件区间如下（显示值取近似；精确值由成功中心和上述规则计算）：

| 家族 | 统一尺寸比 | X 偏移 / mm | Y 偏移 / mm | yaw / ° |
| --- | --- | --- | --- | --- |
| F1 | 1.007721～1.010000 | −0.295～1.205 | −2.322～−0.822 | −0.202～0.098 |
| F2 | 1.007202～1.010000 | 1.786～3.000 | −3.000～−1.878 | −0.872～−0.572 |
| F3 | 0.998000～1.002000 | −0.750～0.750 | −0.750～0.750 | −0.150～0.150 |

先选家族再使用对应区间。不能把 F1 的尺寸区间、F2 的位姿区间和 F3 的路线任意拼接，也不能独立缩放圆环、马蹄和链节。

**以上是候选域，不是整个连续域的可解证明。** 马蹄、目标环、链节及间隙统一缩放，保持它们的比例；固定尺寸的机器人不缩放。两臂预抓点和整个折合段重算 IK，夹爪开度按指垫偏移修正，取环引导同步缩放。后续支撑、抓环和取环都读取实测物理状态重新规划。任意改变椭圆比、轮廓和链长的笛卡尔积暂不开放。

新实例抓取圆环时，持续以重力在环平面中的投影确定抓点，避免追踪随圆环自转的材料点；圆形轮廓的相位不应改变世界坐标下的抓取目标。该修正不适用于椭圆环。旧基础 runner 保留其原执行规则。若姿态变化导致抓环 IK 超限，仍拒绝该候选，没有放宽 IK、接触或穿透门槛。

放置规划也必须适应新的双臂末态。F3 的两个随机候选均已取下圆环，但原 demo 固定的世界坐标落桌点 `(0.12, 0.10)` 超出其当前可达姿态集合。新实例优先尝试这个原位置，再依次检查 `(0.00, 0.10)`、`(-0.12, 0.10)`；高度仍为桌面上方 30 mm。每个位置都经过原有 IK、完整夹爪/谜题/桌面净空及携环路径检查，然后才在物理仿真中执行和松手。落桌位置不是随机标签，实际选择写入规划事件。旧基础 runner 保留单点规则。

## seed 与完整实例

[配置](../../../configs/horseshoe_ring_variants.yaml) 通过现有 `build_variant_episode` / `VariantRng` 取样，共享 RNG 版本仍为 1。没有修改公共 seed 映射，也没有使用依赖批次顺序的全局随机状态。

[生成器](../../../topogym/tasks/horseshoe_ring/variant_generator.py) 接受 `seed / family / attempt / jitter`。家族在首次请求确定，重试不会偷偷换家族。每个输出保存请求 seed、实际采样 seed、重试编号、参数、模板、完整配置、源文件哈希、版本、公共 `EpisodeSpec` 和实例内容哈希。输出明确为 `proposed / physics=not_run / accepted=false`。恢复实例读取保存的 JSON，不重新抽样。

输出文件名、批次大小、调用顺序和进程 worker 数量不参与实例身份；并行生成使用独立进程，Hydra 配置上下文不作为多线程共享接口。有限形状库下不同 seed 选到同一形状是正常现象；尺寸/位置/颜色的实际值另行记录。按原型或动作家族组织数据划分，不能把同一原型的微扰分到不同 split 后宣称未见结构泛化。

```bash
# 仅产生一个候选实例描述，不运行机器人，不生成数据集或视频。
PYTHONPATH=. .venv-gs121-nyx/bin/python -m topogym.tasks.horseshoe_ring.variant_generator \
  --seed 42 --family F2 --output runs/variant_checks/horseshoe_seed42.json
```

省略 `--family` 则按 seed 从三族选择；`--anchor` 冻结尺寸、位置和颜色微扰，仅保留该家族的基础路线。输出必须使用新文件。

`--anchor` 使用本族已成功代表的具体尺寸、位置和材质，不再把三族都重置到同一个零偏移场景。
物理规划仍需重新验证。快照恢复同时核对源文件版本；版本不一致时拒绝运行，不会悄悄替换资产或重新采样。

## 验收入口与数据集接入边界

[验收入口](../../../topogym/tasks/horseshoe_ring/variant_pipeline.py) 实际消费实例快照，使用独立进程执行关节控制，并调用独立验收器。默认同一实例跑 2 ms 和 1 ms 两档；两次分别基于实测状态重规划，不要求轨迹逐位相同。OMPL 随机种子被记录，但计时式规划和接触动力学不承诺跨机器逐位复现，最终执行状态和命令应作为独立证据保存。

```bash
# 只生成并验收一个实例；失败保留原因，最多尝试三次同家族候选。
# 这会运行物理仿真，但不写 H5 或训练数据。
PYTHONPATH=. .venv-gs121-nyx/bin/python -m topogym.tasks.horseshoe_ring.variant_pipeline \
  --seed 42 --family F2 --max-attempts 3 \
  --output runs/variant_checks/horseshoe_seed42_verified
```

只有完整重力执行、链节连接、接触触发抓持、穿透上限、放环后自由落桌静置、实例与证据一致以及家族中间路线目标均通过，才返回 `accepted_instance.json`。未运行、失败、重试耗尽都不能返回“已解决”实例；失败记录写入 `attempts.json`。`--single-dt` 可显式选择单时间步验收，报告保留范围，不能称作半时间步通过。

`accepted_instance.json` 保持原候选快照及其内容哈希，内部的生成时状态仍为 `proposed`；实际放行状态来自返回值的 `qualification.accepted` 和对应的 `qualification.json`。流水线须保存并同时读取这两部分，不能修改输入快照中的成功标签或仅凭文件存在判断验收范围。

后续 dataset runner 应调用 `generate_validated(...)` 并读取返回的同一实例和执行证据，再接双臂 writer；不应从 demo 文件名反推出场景。当前实时 agent adapter 仍是固定起点接口，未自动切换为这个生成器；数据 writer 的 ALOHA 适配也属于后续工作。本轮不创建 H5。

`EpisodeSpec` 保存生成输入与身份，运行目录另外保存实际初始化 `source_motion.json`、规划和 `physical_states.jsonl`（实测关节及目标关节、物体状态、时间戳和抓持事件）。预抓持初始化应由这个任务的 runner 完成，不能只把配置交给裸 `build_scene` 后省略初始化/辅助约束。实例快照的 `run.output` 留空且 `record_video=false`，由调用方指定新的运行目录；生成器不再继承历史 demo 的输出位置。

接入轨迹读取时，生成参数的角度单位约定不能用于机器人关节数组：`qpos / target_qpos` 共 16 列，两臂各含 6 个弧度制转动关节及 2 个米制指关节；列映射来自机器人配置。实际物体 `pos` 为世界坐标米、`quat_wxyz` 按字段名排序；初始化/几何引导中的物体位姿相对机器人安装坐标，`quat` 为 XYZW。应按这些字段映射到未来双臂 writer，不能把 16 列直接当作标准 14 维 ALOHA 动作。

预抓持和接触触发的理想辅助抓持继续明确记录；资格不包含纯摩擦抓取或桌面自主拾取。改变轮廓、椭圆比、链长或机器人控制配置后，必须分别新增绑定原型/路径并重新验收，不能继承旧视频的成功标签。
