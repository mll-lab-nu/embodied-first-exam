# TopoGym 翻新后 10 项任务：环境搭建难度与部署方案

日期：2026-09-15。状态：**供人工 review 的部署提案；首批工程已启动，实际验证范围见实际运行报告。**

本次修订已结合用户提供的 Wang 视频来源，更新 #1 Claws 与 #2 三环穿绳的参考结构、资产入口和部署判断。

本轮以新确定的 10 项任务为范围。旧任务、旧分类和已有 demo 仅作为可复用的工程基础，不代替这 10 项任务的交付。

代码目录已拆分：新任务在 `topogym/tasks/`，历史实现位于 `legacy/topogym/tasks_legacy/`；目录迁移后的首批工程工作见[首晚工程清单](ten_task_first_night_plan_zh.md)。

**建议先交付开锁和 3D 电流棒的环境，再扩展刺球出笼与绳穿环；与此同时尽早核对指定解困零件的资产，并做链环接触、单结自接触的小规模物理试验。** 最主要的风险是窄槽碰撞几何失真、多接触柔性体不稳定，以及双臂场景尚需建设。复杂刚体不一定比软体容易：一个被凸包封住的出口，会直接改变任务是否可解。

## 1. 本阶段交付到哪里

本文件只评估两件事：

1. **物理模拟稳定**：环境能重复初始化、静置、承受代表性接触和释放；关键通路没有被碰撞近似改坏，绳与链不会通过穿透改变关系。
2. **变体参数清晰**：知道哪些量可变、单位是什么、哪些量应联动派生、哪些组合无效；给定 seed 能复现相同场景，首批发布范围有检查证据。

包含资产、碰撞体、材料、连接与支撑、单／双臂实体、相机、初始化、参数生成和环境诊断。暂不部署学习算法，不要求通用 oracle、训练成功率、数据集或统一奖励。

环境验收仍需要少量**参考操作**：例如沿一条已知通路缓慢移动零件、让两段绳相互滑过、把一个链环从松弛拉到受载。这些是检查环境能否承载任务的台架动作，不是要求现在完成求解策略。复杂解困至少需要一条可信的几何解法，避免把不可解模型当成“稳定但很难”的环境；完整机器人自主解法可后置。

下文的尺寸、范围、测试预算和人日均为**建议起点或工程估计**，不是实测可行包络。指定实物／基准以原资产为准；首轮试验失败时缩小发布范围并记录原因，不通过放宽穿透门槛宣称部署完成。

## 2. 十项任务的难度总览

评分为当前代码基础上的**工程部署难度**，不是智能体解题难度：1 = 已有直接复用；2 = 常规适配；3 = 有明确的专项工程；4 = 需要较多建模与接触调试；5 = 有后端能力或任务定义未决风险。

人日包含每项最小环境、首批参数和环境检查，**不含共用双臂底座、外部资产等待、重新开发物理后端或完整机器人解法**。按熟悉本仓库的一名开发者估计，正式排期应在首个物理试验后修订。

Wang 的穿绳使用 MuJoCo 分段胶囊绳。本提案默认复用现有 Genesis FEM 实现相同任务，明确记录这是**物理模型迁移**；若能取得完整原生模型与运行代码，可先将 MuJoCo 原场景作为独立对照，另估适配成本。仅凭网页中的几何、姿态和控制记录，不能恢复全部材料、关节、接触与抓持配置，也不据此承诺直接一键复现。

### 3.2 先做两套接触底座

**刚体底座：** 任务零件保持真实自由度；固定支架才设为固定体。视觉网格与碰撞体分别管理。孔、环、叉口和迷宫槽用解析基本体、显式凸分块或经验证的凹形分解，不能给整个带孔物体取单个凸包。按实体体积和材料密度计算合理质量／惯量；不把几十个碰撞块分别当成可自由运动的刚体。

一个物体内的凸块可作为同一 link 的复合形状，但独立物体的初态不能靠重叠装在一起。先对原几何和碰撞表示同时做“应通／应阻”路径检查：可行路径被封住和非法路径被放开都算建模失败。接触正常时零件会受阻、滑动或分开；不能把预定运动关系写成隐藏导轨来代替几何互锁。

**绳／导线底座：** 首选已有 FEM + IPC 管状实体，小规模验证通过后再加绳数、曲率和接触密度。自由段由求解器推进；只有明示的固定端或被夹持局部接受约束。需要区分自身相邻网格面与远处绳段接触，不能为避免报错把整根绳的自碰撞关掉。

若细长比导致体积 FEM 成本或弯曲响应不适用，再单独评估带弯曲、扭转和自接触的 rod 后端。离散弹性杆是一个有研究依据的候选，但当前仓库没有据此验证的新后端，不能把“换成杆模型”当作零成本切换。[Discrete Elastic Rods 作者项目页](https://www.cs.columbia.edu/cg/rods/index.html)。IPC 的接触算法背景也不等于本仓库所有耦合边界、碰撞过滤和抓持方式都自动可靠。[IPC 作者参考实现](https://github.com/ipc-sim/IPC)。

### 3.3 双臂是共用环境工作，单独计预算

建议共用底座先预留 **4–7 人日**，不含自主协作策略。正式构型遵循用户清单：2 双臂为主；5、6、7、8 双臂；1、4、9 按已批准的单／双臂构型部署；3、10 单臂。

- 两台机器人使用相同时间轴，各自保存 base、关节映射、夹爪状态、抓持对象、腕相机外参。初始建议从桌面相对两侧布置，最终 base 距离由整臂碰撞和共同可达空间检查确定。
- 检查两臂互碰、各自自碰、手指—任务物体和机械臂—支架接触。共享桌面尺寸不够时显式增加双臂 preset，不能把手臂部分放在桌外而复用原检查结论。
- 两手抓同一绳时，抓持按对象 ID 与材料弧长段登记，禁止同一网格区域被两个不兼容的位置目标同时强制约束；记录松手和交接的实际状态。
- 环境阶段允许接触确认后启用已声明的抓持辅助，但不能自动固定整条绳、整个链组或未抓住的零件。所有辅助在报告中列出。
- 单臂 + 可见固定夹具可用于早期台架隔离问题，但标为 `fixture_probe`。用户指定双臂的任务，只有双臂实体、抓持和代表性接触通过后才计为正式环境部署完成。

### 3.4 变体分四层，先发布少量可验证的范围

| 类型 | 内容 | 首轮处理 |
| --- | --- | --- |
| 结构轴 | 孔／刺／环数量、槽模板、手性、穿入顺序、链长等 | 每项只选 1–3 个关键轴；通过构造保证结构合理，再做检查 |
| 公差轴 | 孔口净空、槽宽、刺与笼条距离、绳圈大小 | 用无量纲比值或明确的 mm 范围定义，和物体尺寸联动派生 |
| 布局轴 | 桌面位置、整体 yaw、合法初始相对姿态 | 仍需重查支撑与可达性；不把任意 SO(3) 旋转当作重力下等价 |
| 固定物理／数值项 | 密度、材料模型、摩擦、网格、子步、收敛容差 | 第一版固定。以后开展材料变化时单独建 profile；求解器精度不充当任务难度轴 |

每个参数记录：字段名、物理意义、单位、默认值、候选范围、采样方式、依赖量、无效条件、检查方法和配置版本。**结构变体有限也可以清晰交付**：Coil／Keyhole 第一版只有原结构加布局和有限净空变化，比声称任意槽型都可生成更可靠；此时标明“结构多样性尚未完成”。

### 3.5 统一的环境检查流程

以下是建议首轮预算，针对准备发布的少量模板；不是十项任务已取得的结果。

| 阶段 | 具体检查 | 通过后说明什么 |
| --- | --- | --- |
| G0：几何与初始化 | 单位／法线／网格质量、孔道、固定关系、无非法初始重叠；同 seed 的参数和资产哈希一致；复杂解困保存可信的几何参考路径 | 模型表达了想要的结构，存在已检查的可行实例 |
| G1：静置与局部接触 | 5 s 静置 + 10–20 s 代表性轻推／旋转／绳段滑动／松手；量测状态有限性、穿透、漂移、接触抖动、约束释放 | 声明的物理模型能稳定承受关键相互作用 |
| G2：首批参数范围 | 约 1,000 组廉价几何采样；每个离散模板至少 1 个完整接触试验；再覆盖至少 10 个有效 seed 及 8–16 个关键边界组合；选 3 个 seed 各重复 3 次 | 首批参数不是单个好看场景，失败可按几何／数值／可达性归因 |
| G3：分辨率敏感性与交付 | 最窄通道和最密接触各做减半时间步／加密接触几何对照；报告步耗时、峰值显存、冷启动及缓存启动时间；导出配置与诊断视频 | 关键结论不靠偶然漏碰撞成立，团队能够复现 |

几何采样数量不等于物理试验数量。只有通过完整几何解法或对应物理检查的模板范围才发布；不能用包围盒装得下证明存在解法。记录拒绝原因和拒绝率，反复大量拒绝时重写构造规则，避免默默改变采样分布。

**数值门槛按尺度制定。** 定义最窄通路的设计净空 `g`、两表面的碰撞近似误差 `e_A/e_B`、允许穿透 `p` 和探针控制误差 `e_track`。先预算 `g` 大于这些误差与额外余量之和，再用实际通过／阻挡试验验收；这是工程筛选，不是全局可行性证明。这里的 `g` 是配合通路的余量，不是滑动接触面必须始终保持的正距离。

时间离散可先按每子步最大表面位移（平移加转动扫掠）小于关键细节尺度的约 1/4 限速，再做时间步收敛检查。这只是起始规则，不能替代连续碰撞检测。旧锁任务的 2 mm 停止门不能直接用于毫米级导线／槽口；IPC 的 `contact_d_hat` 是接触激活尺度，也不是允许穿透值。刚体报告穿透和惯性异常；FEM 额外报告单元体积比、应变、材料长度变化与非相邻绳段穿越事件。

合法接触试验必须让被测任务对象经过求解器响应。几何离线检查可以输入位姿序列，但仅凭 `set_pose` 动画不能宣称物理稳定。确认无接触时应不碰，安排轻微越界时应被挡住／产生事件，是每个环境都应保留的一对检查。

## 4. 各任务的具体部署

### 4.1 嵌合体脱困 Interlocked Claws

**最小场景。** 对齐 Wang 的双臂 Claw：两件弯曲、分叉的刚性零件从已夹持的互锁姿态开始，通过连续调整相对位姿分离，随后分别落到可见支撑。第一版保留预夹持初态，将从桌面抓起留作另一个初始化构型；不能据此声称已完成自主拾取。单臂版本需要显式夹具和可行路径，不能直接沿用双臂配置。此处的关键约束是几何互锁，是否另外依赖摩擦自锁需在接触试验中核实。

**资产和路径入口。** 作者的 [Claw manifest](https://qinengwang-aiden.github.io/demos/constraint_demos/data/claw/manifest.json) 给出两件 OBJ、抓持变换和机器人记录。几何与物体参考解法来自 [C-Space Tunnel Discovery for Puzzle Path Planning 的官方补充材料](https://xinyazhang.gitlab.io/puzzletunneldiscovery/)，应优先复用，而不是照视频猜形状。导入时按 manifest 保留各自 `source_origin`、`scale` 和变换约定；公开播放映射使用 `scale=0.1`，不能把源坐标直接当米。论文物体路径可用作几何见证；Wang 的 ALOHA 关节记录不能直接输入 Panda。

**物理难点与做法。** 凹爪内侧、弯钩根部和退出窗口最容易被凸分解填实或磨掉。将每件保持为单个刚体 link，显式建立保留凹槽的复合碰撞体；独立检查实际惯量、重心和初态。第一版先保留原尺寸；若夹爪抓不住，整体缩放及新增抓持区域都要作为另一个经 review 的资产版本，不能默认改基准。

本地验收先让受控夹爪／台架对动态零件施加有限速度和力的操作，检查错误直拉被阻挡、正确滑转能通过，再实际松手观察支撑沉降。作者的连续几何检查可指导通路核验，但不能替代这些求解器接触试验；沿路径逐帧改物体位姿只能作为 G0。

| 建议字段 | 第一版范围／来源 | 派生与拒绝条件 |
| --- | --- | --- |
| `geometry.asset_id` | 固定官方 Claw 两件模型及 Wang 的变换版本 | 保存原网格与碰撞体哈希、源坐标换算、初态、参考解法 |
| `geometry.clearance_offset_m` | 默认 0；仅对已指定配合面做小幅偏移候选 | 重查整条参考通路和直拉阻挡；不能改变所有表面后仍沿用旧证明 |
| `init.assembly_pose_id` | 合法装配状态的离散集合 | 不能直接给两件分别加位姿噪声而制造初始重叠 |
| `layout.xy_m / yaw_deg` | 从共享工作区内采样 | 重新检查桌面支撑与全部抓持区域可达 |

**部署次序。** 导入公开原资产、核对尺度与初态 → 用论文路径核验原几何和碰撞表示 → 轻推阻挡和低速滑转台架 → 双臂预夹持、支撑和真实释放 → 少量初态／净空变体；单臂夹具版本单列。

**环境完成条件。** 已知路径在碰撞表示中仍可通过，明确的错误直拉被挡住；低速接触无飞出／穿透解锁，重复 reset 稳定。若只能重建外观，标为资产准备中，不计环境完成。它的参数化难点是“改了爪形还能保持同一类互锁”，第一版不做任意爪形随机化。

### 4.2 绳穿环 Rope Threading

**正式基线。** 对齐 Wang 的 Three-ring Threading：一根未夹持、放在桌面的开放绳，三个有实体碰撞和可见支架的固定环，双臂执行端点抓取、送绳与换手。三个环的位置和朝向不同。单环／双环仍适合排查接触，但属于开发子场景，不能替代正式三环基线；移动环另列构型。

**已取得的尺寸参考。** 作者说明绳长 **1.1 m**，采用 **80 个相连胶囊段、81 个节点、0.5 ms 原生时间步**。公开 [threading geometry](https://qinengwang-aiden.github.io/demos/constraint_demos/data/threading/geometry.json) 中绳段半径为 **4 mm**；每个环由 64 个胶囊段组成，管半径 **6 mm**。由环段中心和半段长还原，环中心线半径为 **75 mm**，名义孔径约 **138 mm**，实际边界仍按分段碰撞体计算。

以下中心与平面法向由公开几何计算得到，单位为米，保留作者场景坐标；法向正负需在导入路线协议时统一。迁到本仓库桌面时对环、支架和初态应用同一个明确的坐标变换，不能只拷贝高度。

| 环 | 中心 `(x, y, z)` | 平面单位法向，正负等价 |
| --- | --- | --- |
| R1 | `(0.075, -0.019, 0.331)` | `(1, 0, 0)` |
| R2 | `(0.010, 0.170, 0.310)` | `(0.8, 0.6, 0)` |
| R3 | `(0.090, 0.315, 0.280)` | `(0.3, 0.9, 0.316228)` |

**物理难点与做法。** 绳穿过的是孔而非视觉圆圈；整个环取凸包会把孔封住。环使用光滑分段的复合实体，限制分段接缝台阶。用现有 FEM + IPC，先做自由端过环、局部弯折、贴边滑动三项测试，再接双臂。末端若加刚性套头，其尺寸、质量与绳的连接方式要显式建模，不默认为裸绳。

将绳长、直径和环布局对齐参考，但 FEM 的弯曲、拉伸和摩擦必须单独标定；不能把 80 个胶囊段等同于 80 段体积网格，也不能直接复制 MuJoCo 时间步就认定稳定。接触后局部辅助抓持可作为首版明示模型。交接需检查先接收、后释放的约束切换，以及双方短暂共同持绳时的冲突；第三环回退用来检查接触与穿套状态是否连续，不硬编码成每局必须出现的动作。

| 建议字段 | 候选起点 | 派生与拒绝条件 |
| --- | --- | --- |
| `rings.count` | 正式基线固定 3；1／2 仅先用于开发检查 | 以后发布不同环数时重建路线、绳长和初态 |
| `rings.pose_template` | 首版登记上述原布局；通过后再加入位置／法向扰动 | 候选可从相对中心 ±10 mm、法向转角 ±5°的小范围筛选，尚未验证；支架、净空、可达性和绳长联动检查 |
| `rope.diameter_m / length_m` | 参考直径 8 mm、长度 1.1 m，首版固定 | 改布局后检查路线、两端抓持长度与余量；不足则拒绝，或显式派生新绳长并形成新模板 |
| `rings.centerline_radius_m / tube_radius_m` | 基线 75 mm／6 mm；孔径约 138 mm，由两者派生 | 首版固定；后续缩孔需按真实夹爪扫掠体积检查，不能只按绳径计算 |
| `route.order / direction` | 原参考最终材料顺序为 `R1−, R2+, R3+` | 必须连同绳的材料方向和环法向约定保存；符号不可脱离约定复制，后续变体另验 |
| `slack_ratio` | 可用长度／参考通路长度，先有充足余量 | 保证双手抓持所需长度，拒绝开局就过度拉伸的实例 |

环分段数、绳离散分辨率、时间步和抓持约束实现存入数值／物理 profile，首版固定，不混入环位置／朝向的任务变体。

**部署次序。** 冻结三环参考几何 → 静置、端点接触与抓持 → 用单环子场景测试贴边滑动 → 双臂交接和局部回退 → 完整三环基线及松手支撑 → 环位置／朝向小范围变体。若取得原 MuJoCo 运行归档，可将其作为对照；当前表中的 5–9 人日仍指现有 Genesis 路线。

**环境完成条件。** 绳段被环实体挡住，合法孔内路径能通过；两手抓持、换手、回退和松开不破坏材料连续性。穿过状态按绳中心线与孔面交点、有限半径净空及两侧材料分布记录，不以手部到达孔后方代替。记录中途额外穿越及消除过程，不能把“任何时刻每环都只能有一次穿越”写成约束。加入两端真实释放、手臂离开孔口后的支撑与低速检查；原演示的数值门槛不能自动当成本后端已通过。参数直观，主要成本在柔性接触和双臂约束适配。

### 4.3 开锁 Lock Picking

**最小场景。** 优先承接现有 `staged_lock`：2–3 片可旋转锁片、固定支架、实体限位和有凸起的钥匙。钥匙自由 6-DOF，锁片由接触带动；不增加按钥匙深度自动转盘的规则。这里是钥匙对孔／插转机构，是否需要最终锁舌动作由本轮 review 决定。

**已有证据。** 现有三片、两次回退实例完成过接触仿真和松手：最大穿透约 0.296 mm，钥匙—机构接触力约 8.165 N。可复用机构与检查代码，但不能把该单例算作全部新参数已验证。[实测记录](../../../legacy/runs/staged_lock_task/nyx_two_required_retreats/report.json)。

| 建议字段 | 第一版范围 | 派生与拒绝条件 |
| --- | --- | --- |
| `lock.disc_count` | 2／3 | 轴向间距、钥匙凸起位置、末端深度同步派生 |
| `lock.slot_template_id` | 先登记已验证孔型，再增模板 | 给定孔型与限位必须有相容通路；拒绝靠大间隙穿过实体的“解” |
| `lock.initial_angles_deg` | 模板内合法初态 | 不与钥匙预先穿插；仍可进入首层 |
| `lock.stop_bounds_deg` | 已验证弧槽范围附近 | 实体止挡与关节设置一致；整圈运动用实际 continuous 关节 |
| `lock.angular_clearance_deg` | 基线为单侧约 4°，扩展后重验 | 孔宽、凸起角宽和制造余量联动；不能独立抽成负间隙 |
| `layout.view_pose` | 以能看清孔阵列的外部近景 + wrist 为基线 | 记录每层关键孔和限位的投影尺寸、遮挡；不以“有三路相机”代替可见性检查 |

**部署次序。** 将已验证实例冻结为环境样板 → 明确插入终点还是转动锁舌 → 首层及后层孔位取景评审 → 增加 2 片／3 片少量模板 → 限位和初态组合检查。

**环境完成条件。** 非法朝向被孔壁挡住，正确朝向可继续推进；限位来自真实结构，钥匙松手不被隐藏约束保持。若后层孔位在真实场景中被遮挡，可调整间距、观察方向或设计可观察的机构版本，明确几何变化；不向正式视觉画面添加透视穿墙信息。暂不要求证明每个模板的最少回退次数。

### 4.4 刺球出笼 Hedgehog in Cage

**最小场景。** 刺球为球心与多根刺构成的**一个刚体**，笼为固定框架；单／双臂通过真实可接触表面操纵球。首版采用已知可装入／取出的模板，避免随机长刺和笼条后靠碰运气找可行实例。

**物理难点与做法。** 细长尖刺易漏碰撞，多个刺同时抵住笼条时接触求解可能抖动。用胶囊或有限圆角的细杆近似刺，记录圆角误差；笼条也尽量避免零厚面。球和刺的复合惯量需合理。只允许预先定义的初态构型，不能在 reset 后凭空缩短刺让它进入笼。

| 建议字段 | 第一版候选 | 派生与拒绝条件 |
| --- | --- | --- |
| `hedgehog.spike_template_id` | 例如 4 刺与 6 刺两个经过解法检查的模板 | 刺数量不是连续加难旋钮；每个模板独立保留退出路径 |
| `hedgehog.spike_lengths_m` | 原型中按核心尺寸定义比例 | 改变某根长度时，重算其完整扫掠与窗口可行性 |
| `cage.window_template_id` | 固定笼条数的少量开口排列 | 球心能过而刺需转姿只是必要筛选，不证明一定可解 |
| `cage.clearance_ratio` | 开口有效宽度／球体直径及刺厚度 | 同时检查“可退出”和“没有被放大成直接整体拿出” |
| `init.orientation_id` | 合法受困姿态集合 | 无初始刺—笼相交；抓持区域不能全部被遮挡 |

**部署次序。** 单刺对笼条碰撞 → 多刺共同接触 → 已知几何装配路径反向核验退出 → 重力下接触台架 → 单／双臂可达性 → 模板内参数。刚体几何路径可反向复用，但带摩擦、重力的物理运动不因几何可逆而自动成功。

**环境完成条件。** 细刺不会跳过笼条，正确转姿后窗口允许通过；10–20 s 多点接触不爆炸。参数困难在可解结构的生成，建议先做模板库，不让所有刺长、刺角、笼距互相独立采样。

### 4.5 光纤收束 Fiber Bundling

> 2026-09-16 更新：用户已明确为“单根粗绳末端分叉细绳，根部固定，细绳无重力但可碰撞变形；单臂只操纵粗绳，穿过窄闭环”。当前实现与参数见 [分叉绳首版](fiber_bundling_zh.md)。下文保留原先独立导线提案作为历史设计记录，不再作为本任务现行定义。

**先确定结构含义。** 若使用一个完整闭合刚环，不能让导线中段直接横穿环壁进入环内。合法改变穿套关系需要自由端过孔，或环从自由端套入；开口／可开合环则是另一种环境。如果导线本来全部穿环，只是在环周围散乱，任务是已穿线的梳理与聚拢，也应单独记录。这个选择决定初态生成器，不是后期可忽略的小参数。

**本提案的默认首版。** 按“多根细导线”做机器人尺度的柔性导线原型，从 **3 根、直径约 3–5 mm** 开始。采用闭合固定环与可穿入的自由端；导线另一端明确固定在可见接线排或保持自由，二者不得混用。双臂各自操作明确导线，之后再扩到 5 根。若 review 选择开口环，则改为显式建模开口／铰链与限位，重新估计。

**物理难点与做法。** 细线的弯曲响应、线—线摩擦和夹持可分辨性都比粗单绳苛刻。先测试两线交叉滑动，再测试三线在环口聚拢；保留每根线独立材料身份和自／互接触，不能把多线合成一根粗绳。FEM 直径缩小会同时改变弯曲、质量和网格质量，不能仅把现有 8–12 mm 绳缩成细线而保持其余参数不变。

| 建议字段 | 第一版候选 | 派生与拒绝条件 |
| --- | --- | --- |
| `bundle.ring_mode` | 待 review：闭环自由端穿入／开口收拢／已穿线梳理 | 三者作为离散任务构型，不按同一初态随机混合 |
| `bundle.wire_count` | 3，再到 5 | 按数目检查环内可容纳截面、夹爪分离抓取和计算成本 |
| `wire.diameter_m / length_m` | 约 3–5 mm；长度按接线排—环的路程加余量派生 | 排除环能装下截面但端头／夹爪无法操作的组合 |
| `bundle.initial_route_template` | 无结的分散扇形、少量可追踪交叉 | 不能把随机点连线形成的穿透／真结叫作散乱初态 |
| `ring.inner_diameter_m` | 先给充足余量，再缩小 | 截面积上限只是粗筛；需检查实际排列与弯曲进入空间 |
| `wire.material_profile` | 首版固定一套弯曲与摩擦 profile | 实测形变／接触后再新增，不能让隐藏摩擦变化混入结构轴 |

**部署次序。** 明确闭合关系 → 单线弯曲与夹取 → 两线摩擦滑动 → 三线与环接触 → 双臂持线与释放 → 五线和布局变体。细线 FEM 不可用时才进入 rod 后端评估，该工作超出表中人日。

**环境完成条件。** 每根线都保持独立连续实体，环内／环外状态来自实际几何，接触不能互穿；三线共同受载和放松均稳定。报告实际分辨率和导线尺度，不宣称模拟了真实光纤的玻璃断裂或微米接触。

### 4.6 环环相扣 Horseshoe Ring

**2026-09-16 实现更新。** 根据用户参考图新增完整双马蹄装配原型：两个开口马蹄件、两条各三链节的短链和一个独立目标圆环。
源码在 `topogym/tasks/horseshoe_ring/geometry.py`、`scene.py`、`demo.py`，配置为 `configs/horseshoe_ring_preview.yaml`。
全部九个零件为独立自由刚体；原三链环试验保留作局部接触回归。链节数、端部连接孔与所有尺寸仍是原型假设，
不等同于照片对应商品的精确 CAD；初始装配检查不代表取环路径和完整物理任务已验证。
详细来源和复现命令见 `assets/tasks/horseshoe_ring/photo_reference_v1/README.md`。

**最小场景。** 按最终确认的实物结构建模马蹄件、连接链和目标圆环，完整保存连接关系。双臂操作马蹄件／圆环；链由若干闭合刚性链环组成，因此“纯刚体”仍可能是一个复杂多体接触系统。

**物理难点与做法。** 相邻链环应能自由转动、滑移、松弛和绷紧；默认用真实闭合环的互穿关系及接触约束。简单铰链／球铰链串可作为性能对照，但通常限制了真实链环相对滑动，不能默认为同一任务。每个链环采用保留孔洞的复合碰撞体；相邻独立环必须保留接触，不能因“链的邻居”就过滤掉。

| 建议字段 | 第一版范围 | 派生与拒绝条件 |
| --- | --- | --- |
| `assembly.template_id` | 一个确认过的实物拓扑 | 保存每条链连接哪两个部位、目标环套在哪一段 |
| `chain.links_per_span` | 基线 N，验证后加入 N±1 | 重新检查折叠所需松弛量，不能只看静态链长 |
| `chain.link_inner_axes_m / wire_diameter_m` | 原资产或测量值 | 相邻环必须可合法穿套，最小孔径大于线径加接触余量 |
| `horseshoe.gap_m / end_geometry` | 只改变经指定的配合尺寸 | 不能出现目标环直接越过端部的捷径，或把原出口彻底封死 |
| `target_ring.inner_diameter_m` | 与马蹄折叠包络和链尺寸共同派生 | 独立检查可行取出路径及未折叠时的阻挡 |
| `init.chain_state_id` | 少量合法松弛链姿态 | 无环—环初始交叠，不使用每环独立噪声 |

**部署次序。** 两环互穿接触 → 三环链悬挂、拉紧、放松 → 完整实物连接 → 目标环与马蹄局部接触 → 双臂实体 → 最短／最长链边界。链初态可在预计算的无穿透装配姿态下创建，随后静置；运行时不关闭碰撞来重新接链。

**环境完成条件。** 链不会脱链、穿环或数值拉断；松弛到绷紧时不持续发散，目标圆环存在合法取出通路。没有确认完整实物解法前，几何参数不能作为正式随机范围发布。这项应尽早用三链环试验判断后端适配成本。

### 4.7 解绳结 Knot Untying

**最小场景。** 一根开放绳上的一个松 overhand knot，双臂允许操作两端或中段。先保证结在声明的初始支撑下可持续存在、两端可操作；不从紧结、高摩擦、多结开始，也不把俯视“8 字交叉”当作单结。

**物理难点与做法。** 结的自接触和摩擦直接决定能否拉动；网格过粗会形成数值卡扣，漏碰撞又会让绳穿过自己。绳的参考态应是声明的直绳或真实预弯材料，不能把打结初态无意注册为无应力形状，随后把回弹解释成绳结机制。已有直绳参考态接口可复用，但对紧曲率下的体积映射仍需检查。

| 建议字段 | 第一版候选 | 派生与拒绝条件 |
| --- | --- | --- |
| `knot.type` | 固定 `overhand` | 其他结型后置，不靠随机曲线生成混合结型 |
| `knot.handedness` | 左／右，分别验证 | 镜像同时更新材料路径、初态和抓取侧，重查可达性 |
| `rope.diameter_m` | 约 8 mm 原型，先固定 | 缩小直径需重新检查网格、摩擦和抓持 |
| `knot.loop_size_over_diameter` | 先筛选约 6–10 的松结模板 | 控制弯曲半径与自接触间距；仅为候选，仍需静置验证 |
| `rope.free_tail_lengths_m` | 两端长度由结区消耗长度和可抓范围派生 | 总弧长守恒；拒绝端头藏在无法接触的位置 |
| `knot.preload_profile` | 松结基线，拉紧程度后置 | 用准备过程或可量测的几何／力定义，不用任意坐标噪声代替松紧 |

**部署次序。** 非相邻绳段交叉滑动 → 无穿透的松结网格与直绳参考态 → 缓慢准备／松弛后的初态缓存 → 局部扩大绳圈、送绳、抽端三个短试验 → 双臂持绳与释放 → 左右手性及尾长边界。也可在有合法材料映射的前提下直接构造弯曲初态；须保存预应变并验证参考／当前单元均有效，不能只重设顶点后归零应力。

**环境完成条件。** 静置后仍是目标初态，代表性松结／送绳过程中无自穿越和网格翻转；松开一只手后不依靠隐藏固定点维持结。记录材料弧长、自接触对和已知准备过程；投影交叉数只作诊断，不单独证明打结／解结。首轮不要求一个可泛化的自主解结算法。

### 4.8 Cast Coil

**最小场景。** 精确的两件 Cast Coil 刚体，双臂操纵。官方描述对应两个近似同形、外观方正的卷绕件，靠滑动与旋转拆开；不能用两个普通螺旋弹簧代替指定谜题。[Hanayama Cast Coil 产品说明](https://hanayama-toys.com/product/cast-coil/)。

**物理难点与做法。** 在多个边角同时接触时，细小凹口决定能否转动。先获取可靠网格／CAD 和参考分离路径，标注转动窗口，再做局部显式分块或高精度碰撞分解。碰撞模型的缝不能产生假出口；模型简化误差必须显著小于实际配合余量。

| 建议字段 | 第一版范围 | 派生与拒绝条件 |
| --- | --- | --- |
| `geometry.asset_id` | 原结构一套 | 原件和“受 Coil 启发的新模板”分别命名 |
| `geometry.scale` | 默认原尺度；夹爪尺度不合适时 review 后选定一个缩放版 | 同时缩放配合、重算质量惯量、检查指垫扫掠；首版不任意随机 |
| `geometry.clearance_profile` | 原配合与少量经检查的放宽版 | 只调整指定配合面；必须仍保留互锁且整条路径可通过 |
| `init.assembly_state_id` | 已知装配分支内的少量状态 | 状态不相交；不得把已接近出口的状态当成同等结构难度 |
| `layout.xy_m / yaw_deg` | 工作区内姿态变化 | 支撑和双臂抓持重新验收 |

**部署次序。** 资产与窗口测量 → 原网格／碰撞体参考路径核验 → 最窄窗口滑转台架 → 两件自由刚体在双臂夹持下的局部运动 → 有限初态和净空范围。

**环境完成条件。** 原解法对应的转动与滑移窗口保留，错误方向被阻挡；物理接触不会靠穿透越过角点。第一版参数化只承诺布局、已验证初态及有限净空。新增圈数、凹口位置或截面形状属于重新设计谜题，不能直接列成独立随机轴。

### 4.9 Cast Keyhole

**最小场景。** 两件具有相互配合凹凸槽的刚体，按确认构型用单臂加可见夹具或双臂。官方描述是由两件平面上的凹凸结构组合成三维迷宫，因此出口与死路必须由实际几何形成。[Hanayama Cast Keyhole 产品说明](https://hanayama-toys.com/product/cast-keyhole/)。

**物理难点与做法。** 内槽深度、窄颈和凸起尺寸共同定义可行姿态，粗网格容易把转弯抹平。先检查槽底、槽壁、跨层区域和出口；把槽分段组成一个刚体，而不是给移动件设置沿路线滑动的隐藏关节。内凹几何难从单段视频恢复，资产输入是主要前置条件。

| 建议字段 | 第一版范围 | 派生与拒绝条件 |
| --- | --- | --- |
| `geometry.asset_id / maze_template_id` | 先固定原结构；新增模板需独立路径证据 | 每个模板记录起点、出口和关键转姿区域 |
| `maze.clearance_profile` | 槽宽减凸起有效宽度的净空档 | 槽宽、凸起、圆角一起核验；保持跨层通路和阻挡关系 |
| `maze.depth_profile` | 首版固定原深度 | 后续改变深度须重查抬升越墙捷径及转动空间 |
| `init.branch_state_id` | 合法起点／分支状态集合 | 不把任务物体随机扔在槽内；记录离出口的结构位置 |
| `layout.pose / support_mode` | 单臂夹具与双臂分别建配置 | 固定方式不能挡住必要出口，也不能凭空增加轴向约束 |

**部署次序。** 精确资产 → 通道与出口核验 → 直槽滑移、转角、窄颈三个台架 → 真实自由度下的接触检查 → 单／双臂场景 → 少量初态变体。

**环境完成条件。** 正确通道可连续通过，死路真实受阻，移动件不能从槽壁直接抬穿出去。结构变体难度最高之一：若要“迷宫拓扑可变”，需另做带路径校验的生成器，第一版不把它承诺成现成能力。

### 4.10 立体电流棒 3D Buzz Wire

**最小场景。** 固定三维金属导线／导轨，单臂抓持带闭合环的刚性手柄。环在 reset 时已合法套在起始段；末端有目标截面，支撑和端部结构防止环从任意一端先脱离再搬到终点。实际物理中不需模拟电路，记录环与线的接触事件即可。

**物理难点与做法。** 导轨用可控三维曲线扫掠有限半径圆管，碰撞可采用足够光滑的分段胶囊／凸块；须检查接缝不会制造假碰撞。移动环与手柄是一件刚体，保留实际闭合孔。小间隙时需要按实际碰撞几何做最小距离与连续扫掠检查，接触力阈值不能替代所有轻触检测。

| 建议字段 | 第一版候选 | 派生与拒绝条件 |
| --- | --- | --- |
| `wire.path_template_id` | 空间 S 形、一个出平面弯、两个出平面弯 | 保持连通开放路径；先不加入近距离自交叉路线 |
| `wire.radius_m` | 约 3–5 mm，固定档起步 | 与离散段长、圆角和碰撞误差共同校验 |
| `loop.inner_radius_m` | 约 15–25 mm 的候选 | 环半径减线半径仅是直线段粗筛；弯曲处需整件环杆扫掠检查 |
| `wire.min_curvature_radius_m` | 约 80–150 mm 起步 | 曲率连续且手柄能转过弯，不只检查环中心能沿曲线走 |
| `wire.out_of_plane_amplitude_m` | 约 30–100 mm 起步 | 支架净空、机械臂高度与腕部姿态可达 |
| `layout.yaw_deg / start_end` | 整体方位及正反方向 | 反向仍需检查机器人可达；两端保持明确标识 |

**部署次序。** 直线段无接触与轻触标定 → 平面单弯 → 出平面弯 → 环杆整件扫掠路径 → 机器人抓持和外部相机 → 曲率及出平面幅度范围。

**环境完成条件。** 已知居中路径不会被碰撞分段误报，故意靠近线时能稳定触发事件；环不能穿线或脱离导轨抄近路。进度可记录沿中心线的位置，但不把位置投影回曲线强行引导环，也不忽略环姿态和手柄碰撞。接触检测按求解子步／连续扫掠记录，不能仅检查 20 FPS 视频帧。

## 5. 部署顺序与停止条件

### 5.1 首批先让工作模式跑通

| 批次 | 交付内容 | 启动条件 | 转入下一批前看什么 |
| --- | --- | --- | --- |
| A | 开锁环境整理；3D Buzz Wire；共用参数／诊断框架；双臂底座初版 | 开锁定义确认；电流棒参数化几何可直接构造 | 刚体“该过则过、该挡则挡”、参数可复现、双臂身份与碰撞正确 |
| B | 刺球出笼、单绳三环基线、Claws；Coil／Keyhole 资产具备时接入 | Claws 原资产导入；有已知合法几何模板；双臂底座通过；绳单体接触通过 | 初态有效、接触稳定、首批模板和边界都有记录 |
| C | Horseshoe Ring、多线收束、松 overhand knot；复杂谜题的结构变体 | 各自小规模试验通过；光纤环型与端点已明确 | 不依赖隐藏约束和穿透；耗时可接受；必要时冻结较小发布范围 |

A/B/C 是交付顺序，不表示高风险试验等到最后才做。**一开始就做三项短试验：三链环松弛／拉紧、松单结自接触、三细线环口滑动。** 每项先用约 1–2 人日定位是否能复用现有后端，该成本计入对应任务估计；不以这个预算承诺拿到稳定结果。

如果 G1 持续失败，先停止扩变体，判断是几何失真、初始化、抓持冲突还是物理后端能力不足。若需新 rod／链动力学后端，单列工程项目和时间，不用增加阻尼、删除关键接触或降低真实自由度掩盖缺口。

### 5.2 建议的人力组织与预算读法

可以按“刚体环境”和“绳／链接触”两条工作线组织，但它们共享双臂、资产规范和诊断工具。共用参数／检查框架适配建议另预留 **2–4 人日**；复杂零件的几何清理算在各任务，避免重复计费。

表中任务人日总和不是可靠的交付日期：指定资产等待、GPU 排队和后端不适用会改变关键路径。先以 **A 批可验收环境 + 三个风险试验结论** 作为第一里程碑，再按实测步耗时、资产质量和剩余物理问题承诺其余排期。环境构建阶段先用无渲染或基础渲染运行检查，通过后再录 Nyx 展示，减少重复渲染成本。
