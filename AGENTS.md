# AGENTS.md — map for coding agents working in this repo

Read `README.md`, `docs/PROTOCOL.md` (the contract, v1.2-rc) and `CONTRIBUTING.md` first.

- Terminology (protocol v1.0): **privileged** mode (formerly unlimited) and **standard** mode (formerly limited,
  wire protocol `eai-standard/2.x`, formerly `rcb-limited/2.x`); v1.1 adds a third mode, **standard-realtime** (standard mode on a
  clock that does not stop, `eai-standard/2.3`, PROTOCOL §4b). Task directories end in `-privileged`, `-standard` or `-standard-realtime`;
  base images are `ghcr.io/mll-lab-nu/eai-<name>`, one image per benchmark (PROTOCOL D5; formerly `rcb-<sim>`). No `results/` in task dirs.
- Generators under `scripts/` end with `scripts/task_conventions.py` (`normalize`): fields, protocol spelling, test.sh, graders,
  README layout, no `results/`. `python3 scripts/task_conventions.py --check tasks/<task>` reports a task it would change.
- Tasks are self-contained Harbor task dirs under `tasks/`. Nothing at run time imports repository code outside the task
  directory; shared sources are copied in by generators. Reference tasks: `tasks/robotwin_2_0_stack_blocks_two-privileged/` and its
  standard-mode twin `tasks/robotwin_2_0_stack_blocks_two-standard/`.
- `images/<sim>/Dockerfile`: simulator base images, tagged from `images/<sim>/VERSION` if present else
  `images/VERSION`; `scripts/build_images.sh`. MuJoCo tasks (`dextoolbench_*`, `mujoco_playground_*`) use `images/mujoco/`
  (run `prepare_assets.sh` first); their standard-mode twins are generated by `scripts/mj_mk_limited.py`, RoboTwin's by
  `scripts/robotwin_mk_limited.py` (inside the eai-robotwin image: needs numpy). KinDER and HumanoidBench tasks are
  rendered by `scripts/{kinder,humanoidbench}/gen_tasks.py render` (`check` must pass); notes in `docs/benchmarks/`.
- Every task declares its minimum compute (PROTOCOL §2.9, v1.1.4): `[metadata.resources]` in `task.toml`, written by
  `task_conventions.normalize` from the rules in `scripts/task_resources.toml`, and the README's `## Compute resources`
  rendered from it; `ci_checks/check-resources.py` checks both.
- Every task declares resource limits and docker caps (PROTOCOL §2.10, v1.1.5): `[metadata.resources.limits]` / `.caps` from
  the `[[limit]]` / `[[cap]]` rules in the same file; `normalize` ends `instruction.md` with the `## Resource limits` paragraph
  rendered from them (generator-owned: edit the rules, never the paragraph). From v1.2 a task-provided monitor
  (`scripts/rcb_monitor/`, copied into every task by `normalize`; `ci_checks/check-monitor.py` runs its tests) and the
  verifier judge them; with `RCB_LIMITS_ENFORCE=1` a violation fails the trial (default 0: recorded only). Declared caps
  are the applied ones: `normalize` sets `[environment].memory_mb` from `caps.main.memory_gb`. A CPU cap above the
  host's CPU count is the runner's to clamp (docker refuses it); the values in `scripts/task_resources.toml` stay.
  The same step's `sanitize` line in every `tests/test.sh` removes links and special files from `/app/output` before
  the grader reads the agent's files.
- `ci_checks/run_all.sh [task dirs]`: contract checks (incl. verifier isolation: `[verifier] environment_mode = "separate"`
  + `tests/Dockerfile`) and the protocol check (`check-protocol.py`). New check =
  `check-<thing>.sh <task_dir>`, registered in `run_all.sh`; a rule that guards the trust boundary or the caps also gets a
  mutation in `ci_checks/check-ci-selftest.py` (a real task broken that way must fail the rule). Run the checks from a
  checkout made with `umask 022` (`run_all.sh` sets it for itself). `ci_checks/check-unit-tests.sh --all` runs the
  service-layer tests that need numpy + requests (CI job `unit-tests`).
- `tasks/dataset.toml`: task manifest with a digest per task; refresh with `cd tasks && harbor add --scan .` after any
  change to a task (`ci_checks/check-dataset-manifest.sh` recomputes the digests).
- Local docker sandbox has no `[environment].gpus`. RoboTwin and MuJoCo tasks pass a GPU through
  with `environment/docker-compose.yaml` (service `main`, nvidia device reservation; `sim` in standard mode) — copy it
  from `tasks/robotwin_2_0_stack_blocks_two-privileged/`.
- Run agents with Harbor's native agents only (`-a codex`, `-a claude-code`); no adapters, and no gateway that holds
  credentials or changes requests. The usage gateway (`scripts/usage_gateway/`, `GATEWAY=1` in `run_agent_batch.sh`;
  official runs use it) forwards model-API calls only (`api_paths.json`; anything else at a provider is a 403), records
  token usage, and is then the agent container's only egress (PROTOCOL D11, §2.11, docs/RUNNING.md). No tool that runs
  outside the container in official runs: the harness's web search is off (`run_agent_batch.sh` default
  `WEB_SEARCH=disabled`), as are account connectors, apps and plugins.
- Every task's agent egress is the model APIs only (`[agent] network_mode = "allowlist"`, the hosts of
  `scripts/set_agent_egress.py`), and `normalize` ends every `instruction.md` with `## External material` (PROTOCOL
  §2.11, generator-owned like `## Resource limits`). A task needs no download at run time: bake it into the image or
  the task directory. Nothing an agent can read (image, tooling, instance metadata) names or locates a solution.
  Unattended batches: `scripts/run_agent_batch.sh` (lanes with per-job claims; configured by environment variables,
  docs/RUNNING.md); its runner-side tools (`log_mirror.py`, `mem_guard.py`, `scan_secrets.py`, `account_failure_check.py`)
  are not task code.
- `eai-standard/2.2` (docs/STANDARD_MODE.md Part 2), served by the BEHAVIOR-1K, RoboLab, RoboWits, RoboPaint and
  MolmoSpaces standard tasks: its layer (`rcb_limited.py` with crash recovery, `rcb_client.py`, `rcb1.py`, `run.sh`) has one source,
  `scripts/eai_standard/` (D9), copied unchanged into every 2.2 task (`check-tooling-identity.sh`); each benchmark adds
  only its adapter `environment/sim/server.py` (`scripts/eai_standard/toy_server.py` is the smallest one).
- `eai-standard/2.4` (docs/STANDARD_MODE.md Part 4, RoboTangle): 2.3 + the operations capability. Its layer is
  `scripts/eai_standard/v2_4/rcb_limited.py` + `rcb_client.py` with 2.2's `rcb1.py` and `run.sh`, copied unchanged
  into every 2.4 task (`check-tooling-identity.sh`).
  `python3 scripts/eai_standard/selftest.py` tests the crash recovery on the CPU in about two minutes.
- Benchmark-level rules (templates, generators, budgets, tooling file names, the world-frame and tooling declarations):
  `docs/benchmarks/<bench>.md`.
