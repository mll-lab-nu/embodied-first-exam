# {{task_dir}}-standard

Standard mode (robot as a service, `eai-standard/2.1`) of `{{task_dir}}`: the same frozen instance and the same
success rule. HumanoidBench runs in the `sim` sidecar (`environment/docker-compose.yaml`, GPU on the sidecar for
rendering), which holds the reward, judges the episode, records it, replays it in a fresh simulator and renders the
replay video; the verifier grades the sidecar's record in a container of its own (`tests/Dockerfile`, no network).

| | |
|---|---|
| mode / sensors | standard: head-camera RGB + joint angles and velocities (HumanoidBench's own `image` and `proprio` sensors), a pelvis IMU and a camera fixed in the room; {{standard_tier}}, no reward; one episode, no reset |
| action space | HumanoidBench's own: {{nu}} normalised position targets, {{control_hz}} Hz, sent in chunks |
| knobs (compose env) | `RCB_RESET_BUDGET` (0), `RCB_OBS_PROPRIO` (1), `RCB_OBS_IMU` (1), `RCB_OBS_ROOM_CAMERA` (1), `RCB_OBS_DEPTH` (0): the defaults are the standard configuration; a run that changes one (`RCB_RESET_BUDGET=50 harbor run ...`) is reported separately, and `episode.jsonl` records the `/spec` it ran under |
| agent API | `environment/rcb_client.py` (its docstring is the reference); `instruction.md` lists the endpoints |

## Verification
`success` = live success (the episode's return reached the pass mark) ∧ replay success ∧ deterministic (the fresh replay
ends in the live run's state), computed in the sidecar; `tests/grade.py` reads `/data/final.json` and copies the
evidence to `/logs/verifier/` (`replay.mp4`). {{oracle_note}}
