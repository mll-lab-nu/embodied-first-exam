# MyoSuite

Ten [MyoSuite](https://github.com/MyoHub/myosuite) tasks (2.12.2, Apache-2.0) on MuJoCo 3.6.0, CPU only, in both modes:
20 task directories, `tasks/myosuite-<family>-i00-{privileged,standard}`. The robot is a musculoskeletal model of a
human limb, the MyoHand (forearm and hand, 39 muscles) or the MyoArm (shoulder, arm and hand, 34 or 63 muscles), and the
only command is **one excitation per muscle**: there is no joint-level controller, so every motion, grasp and
in-hand manipulation has to be built from muscle commands. Generated by `scripts/myosuite/generate.py` (`--check`).

## Task definition
- **Instance.** One frozen instance per family: the env after `seed(0)` and then `reset(seed=0)`, saved by
  `rcb_myosuite.py make-instance` (`scripts/myosuite/instances/<family>.npz`): the MuJoCo integration state of the
  robot's MjData, every numeric model array (resets edit the model: goal sites, object sizes), the env's Python state, and
  a state hash over state and model that every load checks. The MyoChallenge envs draw their goal, mass or size inside
  `reset()` before `reset(seed=)` reseeds, so the env is seeded first (without it the "frozen" instance changed between
  builds).
- **Success** is MyoSuite's own: its `solved` flag (from each env's `get_reward_dict`) has to hold for **1 s** of
  consecutive control steps (**5 s for baoding**: one full orbit of the moving targets), and MyoSuite's `done` ends the
  episode as a failure (object dropped, fingertips off the key, ...). The episode ends at the first success; MyoSuite's
  step budget (50-200 steps) is lifted, so the wall clock is the only budget. Why the holds: a first version counted 0.25 s,
  and agents passed it by sweeping through the goal (or, in baoding, by parking the balls where the moving targets sweep
  past); a 1 s hold of a fixed goal, and one whole orbit in baoding, require really reaching and keeping it.
- **Texts (D7).** The privileged instruction quotes MyoSuite's reward code; the standard instruction states the goal and
  its thresholds in words (distances, angles, hold time), including MyoSuite's own failure thresholds, of which baoding's
  is a height in the world frame ("a ball's height below 1.25 m"). No object or goal position is given in either mode.
- **Budget: 5400 s** (D8, uniform within the benchmark). Muscle-level control on a CPU-rendered simulator is slow to
  explore, and three of the seven positive examples below took a model 74-86 minutes (baoding, obj_reorient, relocate).

## Modes
- **Privileged:** `rcb_myosuite.Session` in the agent's container: reset, the task's observation dict, MuJoCo model and
  data, muscle moment arms, rendering, recording and self-replay. Deliverable `/app/output/trajectory.npz`, `(T, nu)` muscle
  commands, one row per control step.
- **Standard (`eai-standard/2.2`):** the shared layer of `scripts/eai_standard/` and the adapter
  `shared/standard/server.py`: action type `muscle` (`nu` columns, nothing clipped: every real number is a valid command),
  cameras `hand_top` and `hand_side_inter` (close-ups **mounted on the forearm**: they move with pronation; `mount.type =
  "link"`, parent `radius`), `front_view` and `side_view` (static), 640 x 480, depth on request; proprioception = the
  limb's own joints (`q_`, `qd_`, `effort_`: the muscles' generalized force per joint) and muscles (`act_`, `len_`), never
  the key, pen, die, balls or objects; `/kinematics` = the fingertip sites and the camera mounts in the world frame (FK) and
  fingertip-position IK; crash recovery with resume class `exact` (MuJoCo on the CPU is bit-exact in a fresh process).
  The episode ends at success, at the task's failure or when the time is up; the collect hook replays the recorded
  trajectory in two fresh processes.

## Reference solutions and oracle levels
- **full (key_turn, obj_hold, arm_reach):** MyoSuite's own NPG baseline policies (`myosuite/agents/baslines_NPG/`, in
  the wheel) rolled out from the frozen instance and cut at the first success (72, 57 and 128 rows); rounded to float32
  (the standard client's dtype; the rounded rows still succeed), so both modes execute the same rows. The privileged
  oracle hands them in; the standard oracle streams them through the client.
- **none (the other seven):** no reference was validated. The wheel has NPG baselines for pen_twirl, hand_pose and
  hand_reach too, but the pilot found none that succeeds from the frozen instance under the 1 s hold (they predate
  MyoSuite's current models); the MyoChallenge and Reorient8 envs have no NPG baseline. Solvability rests on successful
  model trials (human review, PROTOCOL §2.7, table below).

## Integrity
- The baselines are removed from the image in the same layer that installs MyoSuite (no layer of `eai-myosuite` holds
  them), and no task image has a solution.
- **Agent egress is the model APIs only, in both modes.** The PyPI wheel ships the baselines (the reference solutions
  of three families), and in an earlier standard-mode trial an agent pip-installed `myosuite==2.12.2` in its client
  container and rebuilt the simulator locally to plan offline. With the allowlist, PyPI and GitHub are unreachable.
- The robot wrapper trap: MyoSuite steps the physics in its robot wrapper's own MjData (`base.robot.mj_data`);
  `base.mj_data` is a mirror. Snapshots and the state hash use the robot's data, and a restore writes it back to every
  copy; without that, mid-episode restores silently diverged.
