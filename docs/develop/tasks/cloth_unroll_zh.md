## 1. 场景

抽纸器形制：两根立柱 + 一根水平横梁，布带绕梁两圈，一端垂落并平铺在桌面。夹爪抓平铺段的自由端，贴桌面沿 +y 直线拉动，卷筒绕梁放料。

出厂几何：

| 项 | 值 | 依据 |
|---|---|---|
| 圈数 / 层距 / 净空 | **1.5 / 0.014** / 0.0045 | 层距是实测粒子间距 3.7mm 的 3.8 倍，脱离绑定映射的混淆区（见第 3、4 节） |
| 材料全长 / 带宽 | **0.28** / 0.12 | 补回被加大层距的螺旋多吃的材料 |
| 横梁半径 / 高度 | 0.004 / 0.045 | 原值，未改 |
| 夹具中心 | **[0.040, −0.100]** | 与补料相抵，末位不变 |
| `pull_scale` | **1.30** | 实测 1.12→0.783、1.30→0.875、1.35→0.785、1.45→0.846 |
| `attach_radius` | **0.014** | 卷半径增大后 18mm 的盘会够到垂落段 |
| `max_start_spread_ratio` | **0.50** | 按松卷几何重标，见第 5 节 |

## 2. 已解决：接触链

本轮解决的问题是布料进入桌面。成因有两条，机制不同，且互相牵制。

### 2.1 指垫压布

`HAND_TO_PAD_Z = 0.1029` 指向指垫**中心**，而指垫是半高 8.5mm 的盒子（MJCF `fingertip_pad_collision_1`），**垫尖在 0.1114**。按中心瞄准布面，垫尖就埋进布面下方 8.5mm。

### 2.2 刚性绑定冻结竖直状态

`fix_particles_to_link` 是刚性绑定，被绑粒子**移出碰撞求解**。绑定瞬间处于桌面以下的粒子，此后整个 episode 都在桌面以下，无法恢复。

实测：clearance 20mm 时，闭合动作把抓取点中心压到桌下 1.6mm，绑定将 21 个粒子冻结在该位置，八段拉动全程存在（7205 粒子·帧）。

### 2.3 两者互相牵制

| clearance | `below_particle_steps` | 主导阶段 |
|---|---|---|
| 8mm | 1801 | 下降 |
| 12mm | 1093 | 下降 + 闭合 |
| 20mm | 7205 | 全部八段拉动 |

抬高 clearance 修复 2.1，同时放大 2.2。

### 2.4 采用的方案

**机械臂退出软体耦合**：`robot_material=gs.materials.Rigid(needs_coup=False)`（与绳类任务一致，见 `ring_transfer.py:215`）。指垫此后不能推动布料，2.1 与 2.2 的成因同时消失，`touch_clearance` 得以退回真实接触高度 8.5mm（垫尖与布面相切）。

配套三项：

| 项 | 值 | 作用 |
|---|---|---|
| `touch_clearance` | 0.0085 | 垫尖相切，由指垫几何推出 |
| `hold_pad_height` | true | 补偿手臂在拉动段的恒定 z 欠量（unpleat −8.0mm、unroll −1.4mm，八段不变） |
| `success.penetration_max` | 0.0 | 任一粒子进入桌面即判失败 |

代价：耦合关闭后无任何机制阻止手臂穿过布料，轨迹正确性由脚本保证，不再由求解器兜底。此项已写入 `cloth_unroll.py` / `cloth_unpleat.py` 的构建注释。

### 2.5 判据补上夹爪

布料粒子计数不统计夹爪。实测 `cloth_unpleat` 曾在指垫位于桌面以下 6.6mm 时报 `gates=all_pass`。新增 `pad_tip_mm` 与 `gripper_ok`（垫尖相对布面低于负布厚即判失败），进结果行与退出码。

### 2.6 结果

`below_particle_steps` 由 1801 降至 **0**，`lowest_z_above_table` 恒为 +2.00mm（布的静止高度，出现在第 1 帧），即机械臂全程未将任何粒子压至静止高度以下。

## 3. 已解决：视觉网格的绑定映射

### 3.1 现象与判定

视频中布带呈撕裂状，而全部物理读数正常：

```
particles=2346  parked_outside=0
bbox_x=[-0.028,+0.105]  bbox_y=[-0.062,+0.201]  bbox_z=[+0.922,+0.925]
worst_gap_mm=4.4  median_gap_mm=3.7
below_particle_steps=0
```

材料无逃逸、尺寸正确、平贴桌面、粒子间距均匀。**物理侧无缺陷。**

判定方式：将 `cloth.vis_mode` 由 `visual` 切换为 `particle`（直接绘制求解器粒子，不经过绑定映射），撕裂消失。

### 3.2 成因

`vis_mode="visual"` 绘制的是原始扫掠网格，通过一张绑定映射跟随仿真粒子。该映射在布带出生时建立一次，而出生时布带绕成螺旋：

| 量 | 值 |
|---|---|
| 卷筒层距 `pitch` | 4.5mm |
| 仿真粒子间距（实测中位） | 3.7mm |
| 比值 | 1.22 |

相邻两圈的间距与同层内粒子间距同量级，映射无法区分「同层邻居」与「相邻圈」。部分视觉顶点绑定至错误的圈，展开时被拽至错误位置，视觉网格因此断裂。

误绑的**位移代价**等于被混淆的两层沿材料方向的距离。相邻两圈相距 2πr ≈ 82mm（平均半径 13mm），且卷筒展开时材料整体沿桌面平移最多 195mm，因此单个误绑顶点的位移被放大成横跨整张布的断裂。

### 3.3 修法与验证

层距由 4.5mm 加大至 **14mm**，比值由 1.22 升至 **3.78**，脱离混淆区。2026-08-26 对 `final_oblique.mp4` 抽帧（第 30 / 200 / 380 / 520 帧）确认：布带全程为一整块连续矩形，无孔洞、无断口、无碎片。

## 4. 曾判定为结构性冲突，以及它为何不成立

修复 3.2 需要层距远大于粒子间距（≥3 倍，即 ≥11mm）。当时的判断是「卷筒维持形状需要层与层接触」，两者不相交。

Genesis 1.2.1 的 PBD 布**完全忽略 `bending_compliance`**（2026-08-23 实测，1e-1 至 1e-8 跨七个数量级读数不变），抗弯刚度实际为零，且 PBD 不提供粘附。因此维持「卷着」这一构型只有三条机制：

| 机制 | 层距要求 | 结果 |
|---|---|---|
| 层与层互相压 | ≈ 一个粒子（4mm） | 卷筒成立，绑定映射混淆 |
| 重力压在曲面上 | 无 | 仅上半圈有效，垂落段仍将整片拽离 |
| 运动学钉住 | 无 | 有效，但需管理出生时机、选取规则、释放节奏 |

**该判断的前提有误。**「层与层接触」是卷筒保持**紧密**的条件，而任务只要求料**留在梁上**。14mm 层距的松卷在静置中确实略微散开（设计跨度 0.392 → 实测 0.457，+17%），但 `on_bar=263`，材料没有离开横梁，形态仍是卷。**起始护栏按紧卷标定的 0.45 挡下了一个健康的松卷**，这是判定失误的直接来源。

由此得出一条可预测的规则，对全部布料任务成立：

> 绑定映射在布**出生时建立一次**。因此判据是：**出生那一刻，层与层是否靠得比约 3 倍粒子间距还近。**出生之后叠得多紧都不影响。

对已有任务逐一验证，全部吻合：

| 任务 | 出生时的层 | 是否命中 |
|---|---|---|
| 1.1 对折 | 平铺出生，对折发生在 episode 内 | 否（终态两层仅隔 2mm，比卷筒更紧，却从未出现撕裂） |
| 1.2 展褶 | 出生即带褶，层距 24mm（`pleat.width`），比值 6.5 | 否 |
| 1.3 展卷（旧） | 出生即卷，层距 4.5mm，比值 1.22 | **是** |
| 1.3 展卷（现） | 层距 14mm，比值 3.78 | 否 |
| 1.5 铺桌布 | 平铺出生 / 由仿真弄皱 | 否 |

1.2 与 1.3 的布料参数**逐项相同**（`particle_size`、`rho`、两个摩擦、两个 compliance、两个 relaxation、`air_resistance`、厚度、长宽、网格间距，十三项无一不同），差异全部来自层距在两种形状里的性质：褶宽是自由参数，卷筒层距被下界（粒子尺寸）与上界（层不接触则卷筒松散）夹住。

## 6. 本轮新增的可复用件

以下与 1.3 无关，对全部布料任务成立。

### 6.1 接触方案

见 2.4 与 2.5。`cloth_unpleat` 已同步；其单次实测为 `gates=all_pass`、`single_layer_frac=1.000`、`below_particle_steps=0`。

### 6.2 仪表（`supervision/cloth_fold.py`）

| 读数 | 回答的问题 |
|---|---|
| `particles` / `parked_outside` | 有无粒子逃出求解域（PBD 将其停放至远处角落，不会拉低 `lowest_z`） |
| `bbox_x/y/z` | 材料实际占据的空间 |
| `worst_gap_mm` / `median_gap_mm` | **撕裂检测器**，全集精确最近邻，分块计算，每 `census_every` 步一次 |

`worst_gap` 的意义在于它**不依赖顶点对应**。`stretch_mean` / `stretch_max` / `stretch_frac_over` 在每一次运行中均为 `nan`，因为 Genesis 的重网格化不保顶点顺序（控制 697 → 仿真 2346）。最近邻间距无此依赖，静止时等于粒子间距，局部拉薄表现为最大值显著高于中位数。

实现注意：早期版本对 400 点子采样，密度降至 1/k 会使最近邻距离自身抬高约 √k，读数因此不可用（实测 1.83，低于纯采样应有的 2.45）。现为全集精确计算。

### 6.3 起始护栏的第二种度量

`grasp.min_start_stored_frac`（默认 `null`，沿用旧度量）。`spread_ratio` 量的是水平伸展，在宽鼓上把鼓自身直径与被迫加长的垂落段一并计入，与「料是否还卷着」脱钩。实测大鼓几何读到 0.450（恰在门槛）而 62% 的材料仍在鼓上。新度量为 `on_bar / 总粒子数`。

判据分的是**动作对错**；行程调得好不好由默认值负责，不由门槛兜底。

## 8. 遗留项

- **`overpull` 不构成失败走法** —— 已解决（2026-09-06，§9.9）：第三条门 `over_pull`（布带前端越过铺平位的距离）≤ 0，overpull 走法读 +0.112…+0.161 判失败，oracle 的 `pull_scale` 1.30 → 1.10。
- **`single_layer_frac` 的 ±0.09 摆幅**来源未查。下一个嫌疑是末态静置不足，其次是每次 `observe` 到的抓取点位置不同。
- **`shove` 的位移契约已变更。**原契约「位移与 `unroll` 相同」在本场景不可满足（夹爪到夹具之间仅 34mm 余量），现为「走满可用余量、停在夹具之外」，由 `SHOVE_BAR_CLEARANCE = 0.057`（实测）限制。判据因此可借位移区分两者，该对照不如原设计严格。
- **`grasp.min_start_stored_frac` 与 `cloth.anchor_tail` 默认关闭。**它们是大鼓路线的产物，当前几何用不到，保留是因为实现与实测结论均有价值（见 6.3、6.4）。`cloth.tape` 2026-09-06 改为按材料弧长钉与放后默认开启（§9.8）。

## 9. 变体部署（2026-09-05，离线五项）

### 9.1 场景（所有轴从这一幅画面出发）

任务坐标系：底座在 x = −0.570、y = 0；x 指向远处，y 左右，桌面 z = 0。工作区盒 x ∈ [−0.25, 0.25]、y ∈ [−0.30, 0.30]。

桌上一个小支架：两根立柱在 x = 0.040 ± 0.070、y = −0.100，横梁（半径 4 mm）在 45 mm 高处连两柱，横梁沿 x。一条 28 cm × 12 cm 布带在横梁上绕 1.5 圈、层距 14 mm（卷外径 59 mm），从卷的 +y 侧切向离开，垂 43 mm 到桌面，沿 +y 平铺 58 mm，自由端 y ≈ −0.013。夹爪在离自由端 12 mm 处捏住（抓取点 y ≈ −0.025），贴桌沿 +y 拖 239 mm（铺平位移 184 mm × pull_scale 1.30），停在 y ≈ +0.215。

**术语。** 平铺段 = 布从落地点到自由端躺在桌上的长度（`flat_run`）；抓取点离梁心 = 抓取点到横梁轴线沿 y 的距离，夹爪能靠近横梁的极限实测 57 mm（`SHOVE_BAR_CLEARANCE`）；铺平位移 = 自由端要移动多远布才全平（`flat_travel`，圈数、层距、杆高在它的终点里全部抵消，只改起点）；可达盘 = 圆心 `reach.base_xy` (−0.570, 0)、半径 `reach.max_hand_dist` 0.665 的水平圆（cloth_unpleat 引入的假设；本任务 pull_scale 1.30 那次 GPU 实测手到过离底座 0.647）。

### 9.8 胶带式保持：布卷不中途坠落（2026-09-06）

### 9.9 防过拉：第三条门 `tail_gap`，oracle 改为拉刚好（2026-09-06）

**为什么。** 任务考的是「要拉多少才刚好把布带拉下来」。此前两处都在奖励「拉得够远就行」：oracle 的 `pull_scale` 1.30 自己多拉 30%（1.5 圈多走 55 mm，整条布带被拖着走）；判据对拉过头不罚（09-06 seed 2 回收比 1.106、跨度 288 mm 超过布长仍 PASS，§8 第一条遗留项）。用户先提的「把内端钉在杆上、过拉就扯断」不可行：内端固定时绕杆圈数守恒，卷只会被勒紧不会解开（1.5 圈能放出的料约 87 mm，回收比上限约 0.2）。改用判据：拉过头的可见后果是布带后端被拖离杆脚，判定器从末态直接读。

### 9.11 转轴：横梁改为随拉动转动的辊，布尾粘在辊上（2026-09-06 晚）

### 9.12 只钉尾端：卷身交给重力（2026-09-07）

**为什么。** §9.11 的转轴版把**整卷**都 `fix_particles_to_link` 钉在连杆上（`held=1518`），卷因此被冻结在解析螺旋上，从出生到剥离前一刻都不静置。画面上的后果是用户指出的那一条：**布卷看起来像悬空绕在杆上的一圈松螺旋**，层与层之间 14 mm 的空隙一直张着，端面能直接看进卷芯。

那 14 mm 是渲染要求（层距 ≥ 约 3 倍粒距，否则 `vis_mode="visual"` 的绑定映射分不清相邻两圈，展开时视觉网格被扯开，§3）。但绑定映射**只在布出生那一刻建立一次**，出生之后叠得多紧都不影响（§4 的规则，cloth_fold 是独立证据）。所以「出生按 14 mm 建映射、之后让重力把它压实」在原理上一直是可行的，缺的只是一个能压实它的机制——**而重力本身就是**，只要卷不会因此散架。

**做法。** 一行改动：`Spool.__init__` 里钉住的集合从 `held` 改成 `held[glued]`。

```python
self.cloth.fix_particles_to_link(
    self.link_idx, particles_idx_local=[int(i) for i in held[glued]]
)
```

`held` / `remaining` / `released` 保留为**弧长记账**（`exhausted` → `tear_check` 仍然要读它），但不再对应任何物理约束；`advance()` 里那句对卷身的 `release_particle` 随之成为空操作，已删除，只留 `released` 的记账。

**为什么卷不会散架。** 08-25 那次自由静置读到跨度 0.392 → 0.457（+17% 散开），当时的结论是松卷站得住但会略散。**关键差别是那时没有粘住的尾端**：自由端加垂落段的重量全挂在最外圈上，拉住它的只有层间摩擦，于是最外圈被拽下来。尾端锚在辊上之后，卷解不开，重力就只能把它往里压。
