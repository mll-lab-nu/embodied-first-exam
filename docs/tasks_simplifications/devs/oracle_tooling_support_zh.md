# Oracle 开发工具支持需求汇总

更新日期：2026-10-02。本文从各任务的反馈中提取 oracle 编写需要的工具函数和功能支持，开发集中在 `topogym/planning/calibration_tools/`。已收录 Interlocked Claws 与以 Slotted Post Ring 为主的 FEM／IPC 反馈；其他任务沿用本页追加共性需求。

本轮范围按用户最新约定收敛为“开发中的不便 → 已有工具 → 需要补充的功能”；HPC 资源、仿真 bug 的定位与修复、正式物理参数调整由其他工作负责。

工具工作只提供状态读取、采样记录、参考对照、规划复用、成本统计与开发试验入口；新增工具的接口检查不扩展成原任务的故障复现或求解调参。

本文记录需求与建议，不表示已部署环境、已实现接口或已批准改变任务配置。实际能力以 [calibration_tools README](../../../topogym/planning/calibration_tools/README.md) 为准；[原始工具需求](oracle_development_tools_zh.md) 保留背景，[首版工程计划](calibration_tools_engineering_plan_zh.md) 保留设计与隔离约束。

## 已实现工具与增量需求

本页列的是支持主题，不能把每项都理解为尚无实现；开发者应先使用已有接口，待开发范围只包括缺失的整合、任务适配和自动化。

控制步跟踪与规划缓存已有单独的 [工具实施计划](calibration_tools_tracking_cache_plan_zh.md)。scripted policy 的动作始终按控制步执行；基础目标／实测对照直接按步配对，无需 planner 提供额外进度。物体期望路线才需要可选参考信息，不能把路线进度和物理时钟混为一谈。

| 支持主题 | 当前已实现 | 仍需补充 |
| --- | --- | --- |
| 判断谁顶开手指、物体卡在哪里 | `contacts()` 返回实体／link、接触力和穿透；`inspect()` 返回控制目标、实测指关节位置和物体位姿；`watch()` 捕捉接触／手指变化，`capture_frame()` 提供近景和文字叠加。 | 完整 IPC 接触来源、精确接触点叠加、指垫净间距计算及接触归因；指关节位置不等于两指垫净间距。 |
| 对照规划与实际执行 | 新增跟踪接口复用逐 tick 目标／实测记录，输出控制步误差、首次越界和回溯分支，物体参考通过可选 hook 接入。 | 其他任务参考适配、净空来源核对和真实执行接入验收；缺参考时仍可读机器人误差。 |
| 抓持后避免完整重算 IK | 新增计划缓存、当前状态检查和准备流程，并提供 Keyhole TCP 路点适配器与自定义任务协议。 | 各任务的物体路线／持件验证、局部修正预算和真实规划成本验收；不自动认证 FEM 或连续路径。 |
| 先让物体移动来探索解法 | `set_object_pose()`、`set_relative_pose()`、`pin_object()`、`set_probe_grasp()` 和 `sweep_object()` 已支持 Keyhole 独立几何探查。 | 在真实 FEM／IPC 场景中施加外力或轨迹目标，使绳、连接和接触同步产生动力学响应；当前几何编辑不推进真实物理。 |
| 看清进度、失败和判据状态 | `inspect()` 已返回 `task.result.metrics`、`task.result.reason`、`info.task_success`、`info.goal_evaluation_complete`、`info.evaluation_status` 和 `info.support`。 | 基础版只需统一摘要与报告展示；跨任务历史验收范围的身份匹配另行适配，不能由支持声明推断已通过。 |

实现依据：[状态与事件](../../../topogym/planning/calibration_tools/inspection.py)、[工具 worker](../../../topogym/planning/calibration_tools/worker.py)、[IK 与路径检查](../../../topogym/planning/calibration_tools/kinematics.py)。[首版验收记录](../../../runs/test_results/calibration_tools_20261002_01/README.md) 已包含 Keyhole `very_easy`／`easier` 的短程真实物理、IK／路径检查、探查隔离、按需 Nyx 和回溯验收；本次核对读取了既有记录，未重跑，不将该结果扩大为 IPC 或完整 oracle 已验收。

## 维护约定

- 每条任务反馈保留来源、日期、实例、配置、证据位置和已尝试措施；反馈中的结果与本地核验分别记录。
- 共性需求使用稳定编号；新任务引用已有编号并补充差异，不重复建一套工具。任务路线和策略留在各自 planner，公共诊断、会话与适配入口集中在 `calibration_tools/`。
- 优先级是排期建议：P0 为阻断正常迭代，P1 为明显影响成本或可解性定位，P2 为后续对照研究；不等同于任务难度或已承诺工期。
- 状态区分待核实、待决策、待实现、待验收、已验收；已有基础能力单独标注，不能据此关闭整条需求。关闭时补实现位置、运行环境和验收产物。
- 后续反馈补充负责人和下一步；当前没有分配的负责人统一记为待分配，不代替他人承诺资源或进度。
- 工具接口、诊断与试验调度集中于 `calibration_tools/`；物理同步、约束、机器人碰撞资产、材料和 Task 判据的修复归对应共享模块。工具负责暴露与验证这些能力，不复制物理实现。候选参数与资产版本单独留证，正式采用是独立决策。

### SUP-001 稳定计算节点会话

反馈请求一个 24 h `salloc` 会话（`gpuA100x8` 分区、单卡），或可持续提交候选的常驻 `sbatch` 守护脚本。实际分区、账户、配额、时限及调度政策以目标集群为准；常驻作业本身不能保证不排队。

建议在公共工具入口补集群启动模板和作业状态记录，实际调度由集群提供。验收应覆盖超过反馈中约 45 min 杀进程窗口的一次完整长任务，保存 job ID、节点、时限、退出原因及最后已提交动作。超时或取消后保留失败证据；进程死亡后的恢复沿用重建和动作前缀回放，不能宣称已有跨进程原生 checkpoint。

### SUP-002 CUDA 环境与性能基线

目标环境为计算节点上的 `.venv-gs121-nyx`，`CUDA_TAG` 根据实际驱动和可用轮子确定。环境检查需记录 Python、Genesis、CUDA、Taichi、Nyx 和设备身份，以及缓存目录、磁盘空间与 inode 余量。安装缓存可按反馈迁到 `bfaq` 等有配额的目录，但不能假定该路径在所有节点存在。

验收包含 CUDA 建场、IK／FK、短物理执行和 Nyx 取帧；录像复用共享 `RecordingSession`。针对同一冻结实例分别计时首次编译、建场、抓持后 IK、物理步进、观测、渲染和记录，并比较 CPU 基线与 GPU 结果。CPU float64 到 CUDA 的数值差异也需记录和重新验收。反馈方预期将半小时级迭代缩至几分钟，这是待测目标；GPU 不保证加速所有串行 IK、FCL 或 CPU 工作。

### SUP-003 并发缓存隔离

反馈方观察到同时启动多个 Genesis 进程会 `SIGABRT`，提出为每个进程设置独立 Taichi／Genesis 内核缓存目录。这里保留为排查方向，尚未证明共享缓存就是根因。

建议由启动器在导入或初始化引擎前分配并记录各进程实际使用的缓存目录、输出目录、设备与资源预算；具体配置项按所装版本核对。验收以至少两个独立候选同时运行，分别覆盖冷编译与缓存命中，核对崩溃日志、输出归属、显存／内存峰值和结果一致性。缓存互不覆盖后仍崩溃时继续定位，不能只凭路径不同就关闭需求。资源保护沿用现有约定：CPU 监控，系统内存达到 90% 停止本轮拥有的相关进程。

### SUP-004 规划缓存与局部修正

具体缓存内容、拟议 API、复用决定、局部修正与任务回退合同见 [控制步跟踪与规划缓存计划](calibration_tools_tracking_cache_plan_zh.md)。先提供可独立使用的缓存保存／检查，再串接任务 planner；目前仍是计划，尚未新增运行接口。

反馈请求：实测抓持状态与预检状态偏差在阈值内时复用预检关节路线，只做局部修正，预计每次可省约 20 min。建议允许将旧路线作为候选输入；具体复用门槛待决定，缓存命中不继承旧证书或旧执行成功。

建议缓存规则如下：

1. 绑定任务／实例、源码、冻结碰撞网格、尺度、机器人和限位、抓持模式及手物变换、路径／规划参数身份；用于执行的记录另绑定控制、后端、精度及时序配置。
2. 锁定后比较物体及双臂实测状态、两件相对位姿、手物变换、关节分支和接触状态；记录平移／旋转偏差及阈值来源，不能只有一个未说明的“足够接近”。
3. 从实测状态构造接入段并修正受影响路段，重新核对 IK 残差、关节限位、机器人／持件碰撞与物体净空。物体路线仍按冻结网格重新认证；检查范围和采样分辨率写入记录，不把离散检查称为连续证明。
4. 身份不匹配、超过阈值、局部修正失败或净空不足时回退完整规划，输出明确原因。位置和姿态误差需结合持件力臂、瓶颈净空与执行误差预算，阈值不固定照搬 1 mm。
5. 验收同时包含可复用、边界和必须失效的案例，比较规划耗时与最终执行／审计结果。所有正式成功仍来自原初态连续机器人执行及独立验收。

### SUP-005 源码与证据位置

反馈请求完成其工作区的 rebase，并同步 `runs/`、`demos/` 历史证据到 Delta 或提供位置。先确认来源 checkout／commit 和冲突状态，再处理对应工作区；反馈中描述的冲突不自动代表当前仓库仍有冲突。

建议提供证据清单：实例与配置身份、源码 commit 及工作区文件哈希、原运行目录、资格报告、独立审计、完整状态／动作、视频、存储位置与文件哈希。同步后核对清单与引用，可从目标位置独立读取和复现。保留已验收原件；缺少证据时标记缺失，不从 catalog 数字或历史视频推断新实例通过。

### SUP-006 Claws 适配与分层验证

在源码对齐后，复用 `planning/interlocked_claws/` 的任务路线、冻结网格认证及运动学实现，通过 `calibration_tools/` 的适配层统一调用，不另写第二套任务求解器。

分别返回纯物体通路、双臂 IK／机器人碰撞、连续物理执行、独立审计四层结果，附各自配置和失败位置。诊断工具报告继续保持 `formal_qualification=False`。验收需要能复现至少一个已通过实例的诊断过程，以及 hard 某次失败的相对位姿／接触证据；不得把有 740 个可跟随 IK 样本写成 hard 已可物理执行。

### SUP-007 抓持后状态对齐

建议记录抓持建立前后实测物体位姿、手物变换、速度、接触、控制步及锁定事件，量化下沉和俯仰。以锁定后状态构造真实起点，生成并检查初段净空逐渐增大的撤离路径；路径不存在时明确失败。该状态也是 SUP-004 判断缓存能否复用的依据。

验收应在反馈中的约 1.7° 俯仰与 3–6 N 初始顶触情形下，正确暴露起点失配并触发重规划或局部修正。锁定后 1 s 接触容许只记录为该证明所用的审计条件，不提升为所有任务通用规则，也不通过修改 Task 判据消除失败。

### SUP-008 误差与接触联合报告

控制步配对采用 [跟踪工具计划](calibration_tools_tracking_cache_plan_zh.md)：直接复用该步实际生效的关节目标与逐 tick 物理记录，基础版本不要求改 policy；物体目标另以开发参考信息绑定到产生它的 action，保持真实等待、重复目标和反馈修正。

建议在同一时间轴记录逐关节目标／实测误差、可用的增益与力矩信息、TCP 与两件相对位姿误差、规划净空、接触力、引擎穿透和独立三角网格检查。后端不提供的字段明确缺失；已有 `contacts()` 只覆盖所采样 tick 的原生刚体接触缓冲，不代表子步接触全覆盖。

按阶段给出最大值、稳态值及首次越界窗口，阈值与单位随报告保存。可用小角度下“角误差 × 力臂”估计位移量级，但不能代替实测相对位姿。验收须能区分抓持变换失配、肩肘稳态误差、腕转误差和真实楔入；对反馈中的约 1.2 mm 穿透能将引擎与独立 FCL 结果对齐到相同状态、网格和接触对。

IPC 补充：联合显示关节目标、实测滑轨位移、双指净间距、限位余量、原生碰撞体位姿、FEM 最小体积比和永久连接误差。滑轨位移不能当作夹爪净开口，刚体接触缓冲为空也不能解释为没有 IPC 接触。碰撞归因、软抓取得／失效和求解器异常分别关联 SUP-012、SUP-017、SUP-014。

### SUP-009 控制时序与前馈对照

保留 A0 历史管线作为对照候选，先核对源码和执行配置，再分别比较控制 tick、物理子步、轨迹插值、速度／加速度前馈、积分限幅及负载补偿。每次只改变可解释的一组变量，记录跟踪误差、峰值接触力、穿透、进度和停止原因。

反馈将 A0 的“小步长和速度前馈”列为主要差别，但同一反馈还提到原尺度、不同路线及接触审计阈值，因而不足以确认单一原因。当前 easy／medium 的 25 ms 控制 tick 若均分为 40 子步，名义物理步长为 0.625 ms；A0 所述 1–2 ms 并不直接更小，须核实双方实际生效的时钟及参数含义。此处是根据反馈配置的算术核对，尚未实测。

改变腕关节增益、抓持辅助、几何尺度、时间离散或允许接触范围均要单独标明配置身份和资格边界；这些对照不自动改变正式任务。验收产物是可复现的差异报告，而非预先承诺 hard 能通过。

IPC 补充：对反馈中的 2.5 ms 与 10 ms 配置，导出控制周期、World tick、子步数和 IPC 最终 `dt`，分别比较无接触、单手夹持、双手约束和压绳阶段。耗时统计区分原生帧与控制步；更大步长更快不等于数值有效或接触同样准确。

### SUP-010 机器人与 IPC 碰撞体同步

反馈称已在 `world/physics/ipc.py` 将 `enable_rigid_dofs_sync` 改为 `True`，修复 IPC 机器人停在 home 的问题。第一步是取得该补丁、环境版本和前后对照，将“反馈方已修未提交”与“本地已集成”分别记录；当前本地文件未见该设置或暂存／未暂存差异。

建议提供建场及运动后的同步检查：对照 Genesis 与 IPC 中机器人各 link 的位置、姿态和帧号，再做空走、接近、实际触物、回溯续动的短验收。已有 `_check_articulation_sync()` 只检查平移差，不能代替姿态与真实接触验证。通过后再对 Rope、Knot、Orbits、Slotted 逐项记录覆盖，不能从一个开关或单场景结果宣布所有 IPC 接触已修好。

### SUP-011 IPC 刚体辅助抓持

建议评估 IPC 原生的刚体抓持约束，用于端片、环和珠，并支持同一场景中刚体与绳的交接需求。当前普通 rigid weld 被明确禁止用于 IPC，不能仅移除拒绝分支就视为约束生效；工具层负责能力查询和试验，共享物理层负责真实约束及生命周期。

验收覆盖真实接触取得、持载移动、双手交接、释放、丢失、检查点恢复和永久绳端连接保持，记录约束归属及过约束时的收敛表现。辅助模型及目标逐实例声明，纯摩擦与辅助证明分别报告。平面指垫是另一条候选路线，不能预先承诺任一方案必然解决交接。

### SUP-012 指尖几何与手指限位

建议导出同一姿态下的视觉网格、Genesis 碰撞网格和实际 IPC 碰撞表示，提供指尖截面、接触区域和双指间距对照；针对反馈的尖端凸包评估平面指垫候选。资产变更需保留尺寸、质量／惯量及版本差异，并回归纯刚体场景。

限位独立验收：记录左右指的关节名称、单位、指令、实测 qpos、原生约束与越界量，对空载、单指先接触、偏心夹持及双手夹持逐项检查。37 mm 是控制上限；MJCF 的单指物理滑轨范围是 0–41 mm。反馈中的 50–113 mm 若是单指 qpos，对应越过物理上限 9–72 mm；若是双指开口，不能直接比较。原反馈尚缺逐指原始记录，需查明坐标／单位、同步与原生约束；不能以指令被裁剪证明实际限位有效。几何修好不关闭限位缺口，辅助抓持也不能掩盖越界。

### SUP-013 材料网格与接触参数标定

建议提供冻结默认配置与候选配置的差异导出和短试验批次，记录实际接触对摩擦、E、网格顶点／四面体数、接触距离、求解容差与有效时序。候选见下文参数表；调参结果同时报告物理指标和耗时。

最小对照覆盖 68 g 端片悬挂伸长、绳的弯曲／穿槽、7 mm 绳附近的闭指接触、端片交接和解除负载后的稳定性。记录体积反转、连接误差、滑移、接触穿透和收敛；粗网格保留绳径、端部连接与拓扑关系，并对更细网格／更小步长做代表性复验。接触距离是求解参数，不是允许穿透阈值；E 从 50 kPa 到 5 MPa 是 100 倍材料变化，不能仅以提速批准。

### SUP-014 Newton 进展与故障处理

建议在工具可获得的范围内记录原生帧、Newton／线性迭代、残差、接触规模、阶段耗时及 valid／体积／连接状态；引擎未提供的字段标记不可用。达到迭代上限后仍返回的状态须检查有效性，不能将“函数返回”视为成功推进。

复用独立 supervisor，补充 IPC 原生步进展和超时预算；正常取消在控制步边界生效，卡在原生调用时由 watchdog 终止本轮 worker，保留日志和最后已提交边界。不承诺安全打断正在执行的 Newton／GPU 内核，也不假定半步可恢复。若需保存每原生步的证据，必须有相应检查点支持，不能把普通心跳当可恢复状态。

验收包括夹住已受约束刚体和压绳的有界失败案例、可查询的超时回执、取消后重建／回放及失败证据保留。进程内 IPC dump 不直接等于跨进程恢复；长时间挂起的 watchdog 路径可用受控阻塞验证，避免为测试保护机制反复耗费数分钟真实卡顿。

### SUP-015 同一物理模型的物体驱动探索

需要在开发会话中先验证“物体怎么动”，沿用当前 Genesis FEM／IPC 的绳体、端片连接、接触和冻结资产。建议评估有界外力／力矩驱动、轨迹伺服或引擎原生运动学目标，明确每种方式的动力学含义、限幅、时序和约束反力；不通过逐帧 teleport 冒充物理解法。

“先不上机械臂，直接移动物体检查几何路线”已经有工具支持：`set_object_pose`、相对位姿编辑、固定、探查抓持及 `sweep_object`，当前适配范围为 Keyhole。因此本项不重做这套几何接口，增量明确限于真实 FEM／IPC 动力学驱动与其他任务适配。现有 `set_object_pose` 不修改 Env 物理状态，不能用于验证端片运动引起的绳变形和接触响应。

新增能力只给可信开发 owner，不扩充正式 privileged 接口；若需要共享物理扩展点，单独列出。所有驱动、节点或约束干预均标为探索，完整机器人证明仍另行连续执行。

验收先在无机械臂参与的 Slotted 场景运行一段端片过槽或移珠动作，保留完整形变、连接、接触与驱动力证据。旧 MuJoCo 一维绳只作解法参考；不同材料和引擎的通过不能替代当前 FEM／IPC 结果。

### SUP-016 双臂可达域与交接候选

在现有 IK／FK、机器人碰撞检查之上，增加给定实例的左右臂可达候选、共同交接区域和失败原因报告。输入包括机器人基座、场景摆放、抓姿、持件几何、立柱障碍及绳长／永久连接约束；两点到基座的距离只用于初筛，不能替代路径可达性。

验收从 home 分别连续到达候选交接姿态，检查关节余量、双臂／持件／立柱碰撞及绳体可行性，再做短物理交接。移动场景中心是版本化候选，需要重新验证初态、目标区与双臂路径，不能作为无记录的运行修补。

### SUP-017 软抓条件与任务资格诊断

基础状态摘要可作为优先的小改动：直接整理 `inspect()` 已返回的数据，复用 [Env 信息](../../../topogym/simulator/env.py) 和 [Task 状态](../../../topogym/tasks/base.py)，不重新实现判据或修改物理。目标进展取任务自身的 `task.result.metrics`／`task.goal_active`，失败说明取 `task.result.reason` 并结合终止／成功状态解释，判据开关取 `info.goal_evaluation_complete`，判定可用性取 `info.evaluation_status`，支持声明及缺口取 `info.support`；没有统一进度百分比的任务不编造百分比。

第一批可只在工具层补统一摘要、`export_report()` 中的任务状态段和读取示例，验证字段对应、缺失值与成功／失败／未完成状态的区别。这部分属于字段整理与展示，工作量明显小于 IPC 动力学驱动。当前 `export_report()` 尚未汇总上述 Task 状态，`status()` 主要描述 worker／操作进度，不能混为同一接口。

“已验收范围”需区分本次运行与历史证据：当前开发报告固定 `formal_qualification=False`，支持声明也不等于物理验收。已有任务资格元数据和证明 catalog 可作为来源，但跨任务汇总需匹配实例、配置与证据身份；未找到匹配项时显示未知／未核验，不声明没有历史证明。这部分及下述软抓诊断单独适配，不包含在基础摘要的小改动估计内。

建议统一报告软抓的关闭意图、双指接触证据、候选材料带、实际抓取时指距、取得拒绝原因、跟随误差和材料边长比。区分取得门槛与保持门槛，查清反馈中的“几乎全闭合才抓住”发生在哪个条件；不能为通过取得而闭指压坏绳。`max_strain_ratio=1.3` 在当前实现中是材料边长比指标，不能直接等同于整绳伸长率。

资格报告分别列出基础可运行、机器人接触、辅助机制、目标判定启用、阈值校准和完整解题见证。读取当前实际 Task／registry／配置身份，保持它们与历史文档一致；不能把 `goal_complete` 当作“本局已成功”，也不能把未验收能力直接升级为通过。当前本地 Slotted 成功判据已默认启用，反馈中的 `False` 需先对齐版本，不新增一轮开关门控。

### SUP-018 IPC 按需视觉与失败留证

复用已有 `capture_frame`、`watch`、`timings`，按抓持、交接、手指越界、接触异常或体积失效取少量近景，并同步数值窗口。新增 IPC 接触来源和指尖几何叠加；后端没有接触点／力时明确缺失，不能用刚体接触摘要替代完整 IPC 输出。

若执行时关闭 RGB，事后重渲染需要完整 FEM 节点／形变、刚体和机器人状态、资产及源 tick 身份，只有质心或位姿打印不足。保存已提交状态的有界窗口并测量保存成本，未记录的事件前画面不补造。验收检查截图对应同一状态、读取不推进物理，并分别计时纯数值执行、按需取帧与全程 RGB；当前能力不能保证对未适配的 IPC 场景立即可用。

### 已找到的路线

- easy：两次 100° 与 40 mm 耦合旋进，再抽离尖端 35 mm；蓝色件分离后停在系统侧，左臂把棕色件送入目标区。这是来源运行范围，不据此新增当前任务的搬运要求。
- medium：钩件在窗框坐标系中先偏航 15°、侧移约 32 mm，再绕杆轴滚转 36° 穿窗 A；偏航到 50° 后贴第二窗顶部横梁穿窗 B。反馈指出同时穿两窗时侧移约受限在 30 mm，需要偏航配合。
- hard：从 Qineng Wang 演示对应的 `assets/tasks/interlocked_claws/cspace_claw_wang_v1/recorded_motion.json` 经参考 FK 和抓持变换恢复相对路径，按 0.68 缩放、逐点拓宽，再用走廊引导 RRT 重连 72 个里程碑；录制关节姿态作为 IK 软锚。

反馈称路线保存于 `topogym/planning/interlocked_claws/reference_routes.json`，每次运行从冻结网格重新认证。表中的证书值、局部规划净空和实测执行偏差属于不同指标，不能互相替代。
