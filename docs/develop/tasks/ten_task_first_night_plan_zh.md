# 新十项任务：首晚工程清单

## 1. 当前迁移状态

- 原实现已在 [`legacy/topogym/tasks_legacy/`](../../../legacy/topogym/tasks_legacy)，新 [`topogym/tasks/`](../../../topogym/tasks/) 已建立轻量包入口与说明。
- 静态扫描发现 **68 个 Python 文件**仍显式导入原任务路径：`topogym/` 下 20 个、`demos/` 下 28 个、`tests/` 下 20 个。此数包含旧目录内部的引用，是当前快照，不含动态导入。
- 例如，旧开锁 demo 和现有开锁 planner 仍引用 `topogym.tasks.connectivity.*`。新包成立后，这些旧子模块不会自动存在；要先处理准备复用的依赖，再运行对应入口。
- 历史包的 `__init__.py` 会集中导入多个旧任务。即使写成 `from topogym.tasks_legacy.connectivity...`，Python 也会先运行历史包入口；仅改一行前缀未必足够。

今晚先打通首个新任务的依赖链，记录其余历史入口的迁移清单。旧任务能否继续运行，与新十项是否已经实现分别登记。

## 2. 各任务开工前的三项共用工作

### 2.1 先打通一个新任务入口

优先选择开锁：检查旧场景、锁片几何、桌面构建器及接触诊断的依赖，把实际需要的模块适配到拟建的 `topogym/tasks/lock_picking/`。新入口按需加载该任务，避免运行时连带加载全部旧任务。历史 demo 的修复按实际使用范围逐项处理。

**完成标志：** 新包可独立导入；开锁的新入口能够加载配置、构建场景并执行物理步。运行报告记录代码版本和源实现位置，不能只凭 `import` 成功认定环境已运行。

### 2.2 十项先写同一种“基线与参数卡”

每项卡片至少写清以下内容；暂时缺少模型或尺寸的字段标为待获取。

| 内容 | 今晚要确定什么 |
| --- | --- |
| 身份与资产 | 稳定的 `task_id`、几何来源／版本、米制换算、可用资产与待获取资产 |
| 首版构型 | 对象数、固定／自由部件、单／双臂、初态与可见支撑；局部试验采用什么夹具 |
| 参数轴 | 第一批准备变化的 1–3 个量、单位、默认值、派生关系；候选范围和已验证范围分开 |
| 固定配置 | 材料、摩擦、时间步、网格／碰撞分辨率、抓持辅助；求解精度单独记录 |
| 拒绝条件 | 初态相交、出口被封、绳长不足、抓持区不可达等可检查原因 |
| 最小检查 | 静置、合法接触、阻挡与释放各查什么；复杂谜题的可信几何路径从哪里来 |

复用现有配置和 `VariantRng` 的约定，先以固定 baseline 和 seed 记录实例。首晚不把尚未验证的扰动范围标为可发布变体。

### 2.3 建立最小物理诊断输出

从首个开锁入口提取适合复用的记录方式，随后用于其他局部试验。建议每次运行输出到 `runs/environment_bootstrap/<task_id>/<run_id>/`：解析后的参数、资产哈希、seed、物理配置、诊断 JSON，以及一段短视频或关键帧。

首轮采用 **5 s 静置 + 5–10 s 代表性接触／释放**作为起始预算；复杂情况按需延长。记录 NaN／发散、最大穿透、物体漂移、接触响应和耗时；绳额外记录长度变化、单元质量及非相邻段穿越。允许穿透量由该任务的绳径／通道净空制定，不能统一套一个毫米数。

双臂共用底座另开检查项：确认两台 Panda + Robotiq 的命名、关节映射、初始无碰撞和共同可达区域，形成一份初始布局。今晚的单物体或夹具试验可以先行，但不能据此登记双臂环境已完成。

## 3. 十项任务分别先做什么

下面的子包名为拟定名称，尚未创建任务实现。每项都先围绕一个明确风险做检查，完成后再扩大场景。

| # / 任务与拟定子包 | 第一项具体工作 | 第一步的完成标志 | 首批准备明确的变体轴 |
| --- | --- | --- | --- |
| 1 嵌合体脱困 `interlocked_claws` | 获取已定位的两件原模型和物体参考路径，按源变换导入；制作保留叉口的碰撞表示，对照原网格检查通路 | 有资产清单、尺度／初态图；原参考路径可通过碰撞表示，选定的错误直拉受阻。此时先记为几何检查通过，动力学后续实测 | 合法初态 ID、整体布局；配合面净空暂固定 |
| 2 绳穿环 `rope_threading` | 保存 Wang 三环布局作为正式基线；从中取一个环，用现有 FEM 绳做自由端过孔与贴边滑动台架 | 有三环参数卡和单环物理记录；孔内能过、环壁能挡，滑动／释放不发生绳段穿越。单环是开发子场景 | 环位置、法向；绳长 1.1 m、直径 8 mm 先固定 |
| 3 开锁 `lock_picking` | 将已验证的锁片／钥匙结构适配到新入口，冻结一个原有实例；做静置、正确朝向慢插和错误朝向阻挡 | 新入口可运行；钥匙与锁片实际接触，正确通路可进入、错误朝向受阻，有松手记录 | 锁片数、初始角、孔位／限位模板；先登记原实例 |
| 4 刺球出笼 `hedgehog_in_cage` | 先做“单刺碰笼条”的刚体试验，确认细杆碰撞表示；再画出首个少刺笼模板的合法装入／退出几何路径 | 单刺不会在声明速度下越过笼条；有首个模板及通路检查结果。几何路径的反向回放不算动力学解困 | 刺模板、刺长比例、开口模板 |
| 5 光纤收束 `fiber_bundling` | 先做两根独立细线交叉、轻压和滑动的接触试验；首版环型与端点条件按提案登记为待 review，再进入三线环口场景 | 两线连续、可区分，接触不互穿，报告分辨率和耗时；环与端点选择有明确记录 | 线数、直径、初始分散布局；闭环／开口模式先固定一种 |
| 6 环环相扣 `horseshoe_ring` | 先搭三只真实闭合刚性链环，检查合法穿套初态、悬挂、拉紧和放松；同时登记完整玩具资产缺口 | 有三链环物理记录，不穿环、不脱链；链环依赖实体接触，且保留真实滑移自由度 | 链环数、线径／孔径关系；完整马蹄结构等待资产确认 |
| 7 解绳结 `knot_untying` | 生成一个宽松 overhand knot，显式采用直绳参考态；先静置，再轻拉端部并释放 | 有无初始穿透的三维结形和稳定记录；不因错误参考态形成假自锁，不因漏碰撞自动解开 | 结手性、圈径／绳径比、两端余长 |
| 8 Cast Coil `cast_coil` | 先完成指定原模型与解法的资产核对，确定尺度、相对初态、关键滑转窗口及碰撞建模方式 | 拿到可核验的原几何与路径，或明确登记缺失项；有资产才进入“应通／应阻”的通路检查 | 首版原结构固定，仅准备布局与初态模板 |
| 9 Cast Keyhole `cast_keyhole` | 先取得指定原模型和迷宫通路，核对槽截面、出口、窄通道与参考路径；确认碰撞表示不会封槽 | 有资产清单和最窄处剖面／通路检查，或明确登记待获取资产；不以随意槽型替代原任务 | 首版槽结构固定，仅准备布局与合法起点 ID |
| 10 3D 电流棒 `buzz_wire_3d` | 先生成直线加单弯导轨及有厚度的环杆，做居中移动和故意靠壁两组物理台架；通过后再加出平面弯 | 居中通路畅通，越界受阻且能记录接触事件；环杆整体参与碰撞，分段接缝不形成假障碍 | 曲线模板、曲率、出平面幅度；环线净空联动派生 |

Claws／穿绳的原资料和明确尺寸见[部署提案 §1.1、§4.1、§4.2](ten_task_environment_deployment_plan_zh.md)。Coil／Keyhole 没有可信原模型时，第一步的产物就是资产缺口清单，不能把“待获取”写成已部署。

## 4. 今晚的执行优先级

以一名开发者、一个主要仿真进程为排程假设，建议按以下顺序推进。物理试验可能暴露额外问题，不将这份清单理解为十项今晚全部完成的承诺。

1. **先完成新入口与十项参数卡。** 确定依赖边界、基线身份和资产状态；优先处理开锁实际会用到的导入链。
2. **先跑通开锁样板。** 用已有最完整的刚体实例验证新入口、配置、物理步、接触记录和输出方式。
3. **尽早安排一个高风险试验。** 优先三链环，检查刚体后端能否稳定承载真实互套接触；若所需碰撞模型尚未就绪，先做单环绳接触。记录失败原因也算有价值的首晚结果。
4. **时间允许时推进电流棒。** 它不依赖外部复杂资产，适合第二个完整走通构建与诊断流程的任务。
5. **逐项推进剩余首步。** 按上表做资产、几何或局部物理工作，把每项状态写为“待资产／几何已检查／接触已检查／待双臂”等具体状态，并附证据入口。

今晚结束时，review 应能看到：十项的基线与待办、至少一个从新目录运行的物理样板、一个高风险试验的通过／失败记录，以及下一步的明确阻塞点。配置卡写完、图像渲染完成、某个局部试验通过，均只登记对应阶段。
