## Task
RoboOlympics table tennis (`tabletennis-match-wallclock-program-standard`), one match against the scripted opponent (level 1, frozen seed
101), in standard-realtime mode (`eai-standard/2.3`, PROTOCOL §4b): the robot as a service on a clock that does
not stop. The sport runs in the `sim` sidecar (`environment/docker-compose.yaml`; `environment/sim/rcb_realtime.py`
runs the clock, `environment/sim/rcb_olympics.py` is the RoboOlympics adapter, `environment/sim/sport/` the sport's
simulator, referee and opponent), which records every command at the control step it took effect, replays the match in
a fresh process and renders the replay video; the verifier grades the sidecar's record in a container of its own
(`tests/Dockerfile`, no network).

## Difficulty
The agent sees the game only through cameras and has no simulator of its own. A point is decided in a few seconds of
game time, faster than a model's turn even at S = 10, so the agent has to write a perception and control
program (find the ball in the images, fit its flight, choose and time the command) that plays by itself, and
improve it between points and during the match. The opponent returns every ball it can reach; level 1 of
the sport's levels.

## Reference solution
`solution/oracle_play.py` runs the sport's RoboOlympics reference player (`solution/builtin_players.py`: camera images,
the proprio columns and `/spec` only; perception by colour, triangulation, a fitted flight model, the sport's contact
law) through the agent's own client; it wins this instance (PR #106).

## Verification
`success` = live success (the match finished and the agent won it) ∧ replay success ∧ deterministic (the fresh-process
replay of the recorded commands ends in the live run's state), computed in the sidecar. The record is
`trajectory_live.f64` (per control step: the id of the command that took effect, -1 for none, and the `ready` flag) with
`commands.jsonl` (the commands as the sport's action layer lowered them), so the replay re-applies what the live match
applied, whatever the timing; `ticks.f64`, `calls.jsonl` and `submitted.f64` record the timing and every call, and
`final.json` the clock's lag (`max_lag_s`, `stalls`). `match.json` is the replay's summary (score, breaks, commands).
`tests/grade.py` reads `/data/final.json` and copies the evidence to `/logs/verifier/` (`replay.mp4`). A simulator
crash or error is an infrastructure failure (`infra_error = 1`), not the agent's (PROTOCOL §4b). `nop` scores 0: the
match never starts.

## Details
| | |
|---|---|
| sport | You play robot table tennis (ITTF rules with the deviations below) against a scripted opponent: a MuJoCo Franka Panda holding a paddle, at your end of a real-size table, seen only through two cameras. The opponent serves every point (recorded real serves) and returns every ball it can reach; you always receive. One game to 5 points. |
| time | S = 10 (RoboOlympics' official slowdown; `RCB_SLOWDOWN` overrides it, results under another S are reported separately): one 10 ms control step every 0.1 s of wall time; the match starts paused and its clock starts at the first `submit` or `get_obs(seconds > 0)`; after every point a break of 12 s of game time (120 s of wall time) in which the clock runs on and nothing plays, ended early by the agent's `ready` row |
| actions | `stroke`, `rest`, `ready`: the sport's own commands (action level `high`), one per row, effective at the row's control step |
| observation | camera images and the agent's own robot plus the referee's information as proprio columns; no ball or opponent state, no seed |
| budget | 7200 s, no reset (one match is the episode), no privileged twin (PROTOCOL §4b exceptions, `docs/benchmarks/roboolympics.md`) |
| agent API | `environment/rcb_client.py` (the realtime client); `instruction.md` documents the commands, the proprio columns and the cameras |
