## Task
Standard mode (robot as a service, `eai-standard/2.1`) of `humanoidbench-loco-sit-simple-i00-privileged`: the
same frozen instance and the same success rule. HumanoidBench runs in the `sim` sidecar
(`environment/docker-compose.yaml`, GPU on the sidecar for rendering), which holds the reward, judges the
episode, records it, replays it in a fresh simulator and renders the replay video; the verifier grades the
sidecar's record in a container of its own (`tests/Dockerfile`, no network).

Note: the chair is behind the robot and never enters the head cameras' view (floor and horizon only);
`room_camera` (the recording camera frozen at its starting pose) sees both.

## Difficulty
See `humanoidbench-loco-sit-simple-i00-privileged`'s README; here the agent also has no state, no reward and
no simulator of its own, and 50 resets instead of unlimited ones: every try is a real episode on the one
robot.

## Reference solution
`solution/oracle_replay.py` sends the same 999 rows (`solution/sit_simple_actions.npy`) through the client,
one per control step (`dt` = 0.02 s, `interpolate="hold"`), as an agent would send them; the service ends the
episode the moment the return reaches the pass mark. No privileged information at run time.

## Verification
`success` = live success (the episode's return reached the pass mark) ∧ replay success ∧ deterministic (the
fresh replay ends in the live run's state), computed in the sidecar for the last episode (the one after the
last reset; earlier episodes are in `trajectory_live.f64` and `episode.jsonl`, not graded); `tests/grade.py`
reads `/data/final.json` and copies the evidence to `/logs/verifier/` (`replay.mp4`). The oracle
(`solution/solve.sh`) scores 1; `nop` scores 0.

Generated by `scripts/humanoidbench/gen_tasks.py` from `subset.toml`, `templates/standard/` and
`shared/standard/`.

## Compute resources
Minimum allocation for one trial (docs/PROTOCOL.md §2.9; `[metadata.resources]` in `task.toml`). The agent phase counts every container of the trial at once (the agent's, and in standard modes the simulator sidecar); the verifier phase runs after it.

| | Agent phase | Verifier |
|---|---|---|
| CPU cores | 2 | 2 |
| Memory | 3 GB | 2 GB |
| GPU memory | 3 GB | 3 GB |

- GPU: required, any NVIDIA GPU; recommended: any 8 GB+ NVIDIA GPU (RTX 4090 / L4).
- Measured: GPU 1.1-2.3 GB, vram_profile (batch_eval_live per-trial GPU peaks, 10-03..10); memory: privileged container median 2.2 GB (p90 11 GB when agents run parallel rollouts), sim 0.7 GB, mem_guard (docker memory per container, ws-1, 10-02..10); CPU author estimate
- Limits in the agent phase (docs/PROTOCOL.md §2.10; `[metadata.resources.limits]`, shown to the agent in `instruction.md`; always measured and reported, and exceeding one fails the trial only when the run sets `RCB_LIMITS_ENFORCE=1`), the agent's container: no GPU, 8 GiB memory, 512 processes, 20 GiB of new files under `/app`, `/tmp`, `/root`; 60 s within 120 s. Expected peak of the whole trial: 7 GiB GPU memory, 13 GiB memory. Limits measured: GPU: 2.3 GiB (batch_eval_live vram_profile (per-trial GPU peaks by card, 10-03..10)) -> max(1.5 x peak, peak + 4); memory: agent container docker peak 2.3 GiB over 10 samples (mem_guard (docker memory incl. page cache, top-4 containers every 10 min, ws-1, 10-02..10)) -> max(1.5 x peak, peak + 4, 8), at most the 16 GiB cap; whole trial: + the sim service's 5 GiB (docker peak 0.7 GiB, 3 samples); processes 512 and disk 20 GiB: design defaults, not yet measured.

## Details
| | |
|---|---|
| mode / sensors | standard: head-camera RGB + joint angles and velocities (HumanoidBench's own `image` and `proprio` sensors), a pelvis IMU and a camera fixed in the room; no root pose, no chair pose, no reward; 50 resets (a new episode from the frozen start each; only the last episode is graded) |
| action space | HumanoidBench's own: 19 normalised position targets, 50 Hz, sent in chunks |
| knobs (compose env) | `RCB_RESET_BUDGET` (50: HumanoidBench's standard configuration, docs/benchmarks/humanoidbench.md), `RCB_OBS_PROPRIO` (1), `RCB_OBS_IMU` (1), `RCB_OBS_ROOM_CAMERA` (1), `RCB_OBS_DEPTH` (0): the defaults are the standard configuration; a run that changes one (`RCB_RESET_BUDGET=0 harbor run ...`: one episode, no reset) is reported separately, and `episode.jsonl` records the `/spec` it ran under |
| agent API | `environment/rcb_client.py` (its docstring is the reference); `instruction.md` lists the endpoints |
| physics vs upstream | upstream's model (HumanoidBench cb11890) on MuJoCo 3.3.7, not the 3.1.6 upstream pins, whose convex collision reported wrong contacts; results on image 0.1.6 or earlier are other physics and are reported apart (docs/benchmarks/humanoidbench.md, Physics). |

  (docs/benchmarks/humanoidbench.md, Physics). The pass rule and verifier are unchanged, so the task keeps its
  name; results recorded on 0.1.6 are other physics and are reported separately.
- 2026-10-10: the sim service marks `final.json` `finalized` the moment the verdict is written, before the
  replay video is rendered (`video_pending` while it renders), and the collect hook's waits run on the clock,
  inside its timeout: a slow, hung or killed video render no longer turns a graded episode into `infra_error`.
  `reward.json` adds `sim_error` and carries `deterministic` in every branch. The scene, instance and pass
  rule are unchanged, so the task keeps its name; every verdict that was reached before is the same now.
- 2026-10-10 (2; second review round): the sim service refuses a negative `Content-Length` unread (400; it
  read until the client hung up), and a simulator that fails inside `POST /reset` ends the episode as `error`
  (`sim_error = 1`), not `reset`. The scene, instance, pass rule and every verdict reached before are
  unchanged, so the task keeps its name.
