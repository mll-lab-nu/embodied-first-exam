## Task
Standard-realtime mode (robot as a service on a clock that does not stop, `eai-standard/2.3`, PROTOCOL §4b) of
`humanoidbench-loco-walk-i00-privileged`: the same frozen instance and the same success rule as it and as
`humanoidbench-loco-walk-i00-standard`, but time does not stop. Once an episode's clock starts (its first
`submit`), the robot runs at 50 Hz in real time and holds its last servo targets while the agent thinks, so
the agent drives it with a controller program of its own that streams targets through the client.
HumanoidBench runs in the `sim` sidecar (`environment/docker-compose.yaml`, GPU on the sidecar for rendering;
`environment/sim/rcb_realtime.py` runs the clock), which holds the reward, judges the episode, records every
control step it ran, replays the last episode in a fresh simulator and renders the replay video; the verifier
grades the sidecar's record in a container of its own (`tests/Dockerfile`, no network).

Note: the head cameras see flat floor and the horizon (there is nothing else in the scene). `room_camera`
stands behind and above the start and looks down the course (`RCB_ROOM_CAMERA_POSE` in the compose file): the
robot stays in frame from x = 0 to 20 m.

## Difficulty
See `humanoidbench-loco-walk-i00-privileged`'s README; here the agent also has no state, no reward and no
simulator of its own, and 50 resets instead of unlimited ones, as in `humanoidbench-loco-walk-i00-standard`.
On top of that the robot does not wait: a model's turn takes seconds and the H1 falls within a few seconds of
robot time without active balance, so the agent cannot steer it turn by turn. It has to write a controller
that closes the loop at the control rate from proprioception, run it in the background, and improve it between
episodes from what it observed.

## Reference solution
None. Requiring one would cap the benchmark at what we can already solve, which systematically removes the
interesting tasks. What replaces it (docs/PROTOCOL.md §2.7): the floor above (doing nothing cannot pass), the
evidence that the task has a solution (`oracle_evidence` in task.toml), and a human reviewer.

## Verification
`success` = live success (the episode's return reached the pass mark) ∧ replay success ∧ deterministic (the
fresh replay ends in the live run's state), computed in the sidecar for the last episode. The replay
re-executes the servo targets the simulator applied at each control step (`trajectory_live.f64`), not the ones
the agent submitted, so it equals the live run whatever the timing was; `ticks.f64` records each step's wall
time and the call that planned it, `calls.jsonl` and `submitted.f64` every call and every row as sent, and
`final.json` the clock's lag (`max_lag_s`, `stalls`) and the held and late steps. `tests/grade.py` reads
`/data/final.json` and copies the evidence to `/logs/verifier/` (`replay.mp4`). A simulator crash or error is
an infrastructure failure (`infra_error = 1`), not the agent's (PROTOCOL §4b). No oracle; human review in PR
#83. `nop` scores 0.

Generated by `scripts/humanoidbench/gen_tasks.py` from `subset.toml`, `templates/realtime/`,
`templates/standard/`, `shared/standard/` and `shared/realtime/`.

## Details
| | |
|---|---|
| mode / sensors | standard-realtime: head-camera RGB + joint angles and velocities (HumanoidBench's own `image` and `proprio` sensors), a pelvis IMU and a camera fixed in the room; no root pose, no base velocity, no reward; 50 resets (a new episode from the frozen start each, paused until its first `submit`; only the last episode is graded) |
| time | the episode's clock starts at its first `submit` (or `get_obs(seconds > 0)`) and runs one control step every 0.02 s of wall time until the episode ends; `submit` writes a plan of future targets (from step `at`) and answers at once; the last target is held when the plan runs out |
| action space | HumanoidBench's own: 19 normalised position targets, 50 Hz, streamed one row at a time or in chunks of up to 10 s |
| knobs (compose env) | `RCB_SLOWDOWN` (1: real time, the official configuration; S: one control step every S x 0.02 s, results reported apart from S = 1), `RCB_RESET_BUDGET` (50: HumanoidBench's configuration, an exception to the mode's default of 0, PROTOCOL §4.5), `RCB_OBS_PROPRIO` (1), `RCB_OBS_IMU` (1), `RCB_OBS_ROOM_CAMERA` (1), `RCB_OBS_DEPTH` (0): the defaults are this task's configuration; a run that changes one is reported separately, and `episode.jsonl` records the `/spec` it ran under |
| agent API | `environment/rcb_client.py` (the realtime client; its docstring is the reference); `instruction.md` lists the endpoints |
| physics vs upstream | upstream's model (HumanoidBench cb11890) on MuJoCo 3.3.7, not the 3.1.6 upstream pins, whose convex collision reported wrong contacts; results on image 0.1.6 or earlier are other physics and are reported apart (docs/benchmarks/humanoidbench.md, Physics). |
