## Task
A ball is thrown high into the air when the episode starts and comes down near the left Panda. The left arm catches it in its cup and throws it through the air to the right arm, whose cup must have moved from its start to catch it. The right arm carries the ball to a second transfer region and throws it back. The left arm catches it again and delivers it into an open box that slides back and forth along a rail, where the ball must settle while the box is moving. The deliverable is one replayable trajectory of 100 Hz joint-target actions (`/app/output/trajectory.npz`,
16 values per row), graded by the task's own staged success check: 6 phases (`left_initial_catch`, `left_to_right_flight`, `right_catch`, `second_region`, `right_to_left_flight`, `left_catch_and_deliver`), in order,
with no failure event and no safety-limit violation, within the task's horizon of 25 s.

## Difficulty
Three catches in shallow 28 mm cups, two of them of a ball thrown by the other arm. Both throws must be real flights, and the two arms must never touch while working in a shared space. The final release must land in an oscillating box during one of its fast stretches. Privileged mode gives the full simulator state (every object's pose and velocity, the fixtures, the
announced goals), the parameters, unlimited exact resets and snapshots, and self-replay; the tooling offers only joint
targets and kinematics. This mode is the control for the standard twin.

## Reference solution
`solution/oracle_actions.npy` (1478 control steps, run by `solution/oracle.py` through the agent's own tooling): a
recorded rollout of this instance by the benchmark's reference controller, which reads the simulator's true state in closed
loop, replayed open-loop. The reference controllers and their recordings are not in the image, and the agent's network
reaches only the model APIs and the package registries.

## Verification
`tests/grade.py` in a separate sandbox: two replays, each in a fresh process, from the verifier's own copy of the instance
(`tests/instance.json`; the rebuilt start is checked against its hash); pass iff the task's success check holds in both
(every phase complete, no failure) and both end in the same state (`deterministic`), plus `/logs/verifier/replay.mp4`
(overview camera). Oracle: 1478 control steps (14.78 s simulated), success at the last one; the oracle
run and two fresh-process replays end in the same state (hash `d44ab7f5729bad52`), and the rollout reproduces the physical
state the benchmark recorded for it after every control step, bit for bit. `nop`: no trajectory, reward 0; a trajectory that
holds the arm still fails (the benchmark's parked controls never succeeded).
