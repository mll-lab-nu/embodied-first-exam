TopoGym×VLA

TopoGym 仿真器概览，VLA 从哪里接入、接口怎么设计，以及首批评测哪几个 VLA。左边是 Gym，右边是 VLA，中间只有一个三类数据结构的协议。

代码库

Genesis 1.2.1 上的机器人拓扑操作仿真器，13 类任务。9 个任务用 ALOHA 双臂，4 个用 Panda 单臂。VLA 在评测循环的 agent.act(obs) 处接入。

接口

模型与环境分进程：模型做服务端（TCP，Python 标准库），评测进程驱动循环。Gym 侧一个通用适配器（每种机器人只有一行常量），VLA 侧按模型写子类。录像在 Gym 侧完成，不需要 Harbor。

选型

每个系列选一个：π0.5、GR00T N1.7、X-VLA-0.9B、DM0.5。只评测阶段按 checkpoint 匹配：Panda 用 π0.5 / GR00T / MolmoAct2 的 DROID 版，ALOHA 用 π0.5-base 与 X-VLA-RoboTwin2。π0.7 等更新的模型未开放权重。

01TopoGym 代码库

TopoGym 是基于 Genesis 1.2.1 的机器人拓扑操作仿真器：解环、分离互锁件、穿绳、解结、铺布。topogym/ 包提供 gym 式接口 make → reset(seed) → interaction() → step(action)。物理由 Genesis 计算（刚体、PBD 布料、FEM/IPC 柔体），RGB 由 Nyx 渲染（compact_lab 场景，848×480）。

仓库中另有 Harbor 层（tasks/ 等目录），用于评测写代码控制机器人的 LLM agent。它与 VLA 接入是并行的两条线，本文只在讨论部署形态时提到它。

一个控制步

现有事实对 VLA 接口的影响
一个进程只能有一个活跃 Env（Genesis 全局状态）多任务评测逐个 with make()，或开多个仿真进程
关节或夹爪越界时 step 抛 ValueError，不自动截断适配器必须截断
夹爪是原生关节坐标（米 / 弧度），不是开口宽度适配器负责归一化与反归一化
13 个任务中 11 个有英文指令：5 个是 instruction 类属性，6 个 placement 任务经 obs["task"]["instruction"] 公开；cast_coil、blanket_flatten 没有需要一份版本化的 instruction 文件，补 2 条
架构测试禁止 topogym.policies；docs/vla_doc 要求不改 simulator/、tasks/VLA 代码放在仓库根 vla/，不放进 topogym/ 包

02VLA 从哪里接入

VLA 只在两处接入：训练时读取从 TopoGym 导出的数据集；评测时在每个控制步的 agent.act(obs) 里被调用。建场景、推进物理、判定成败、录像、记结果都由 Gym 侧完成。

整体流程

评测主循环（伪代码）

下面三段是完整链路。绿色高亮是 VLA 介入的位置，其余都是 TopoGym 已有接口。

# ── ① Gym 环境：vla/gym/run_eval.py（管理方） ──
client = RemoteClient(args.policy)                     # 连接 VLA 服务
spec   = client.spec                                   ← 握手：服务端发来 PolicySpec
cfg = dict(robot_id=spec.embodiment,                   # aloha / panda_robotiq
           control_mode=MODE[spec.action_space],       # joint_abs → JOINT_ABS，ee_abs → EE_ABS
           observation_mode=OBS[spec.action_space],    # ee_abs 时切到 EE，拿 TCP 位姿
           control_decimation=int(400 / spec.control_hz))  # 物理 tick 400 Hz；50 Hz → 8
agent = VLAAgent(client, instruction=INSTRUCTIONS[args.task])

with topogym.make(args.task, variation_id=args.variation, **cfg) as env:
    for seed in args.seeds:
        env.reset(seed=seed)                           # 管理方：重建场景
        actor = env.interaction()                      # 操作方句柄：只有 step / observe
        agent.initialize({"action_spec": actor.action_spec})   ← client.reset(seed)：服务端清状态、设随机种子
        with episode_recorder(env, out / f"seed_{seed}", enabled=args.record):   # 见 3.3，可关
            obs = actor.observe()
            while True:
                action = agent.act(obs)                ← VLA 介入：队列空时 client.infer(Observation) → ActionChunk
                obs, _, terminated, truncated, info = actor.step(action)
                if terminated or truncated: break
        write_result(seed, classify(info))             # success / task_failure / time_limit / unevaluated …

# ── ② Gym 环境：vla/gym/agent.py ──
def act(self, obs):
    if not self.queue:
        o = self.adapter.observation(obs, self.instruction)   # TopoGym obs → Observation（选相机、缩放、拼 state）
        chunk = self.client.infer(o)                          ← 网络调用：一次推理，返回 (H, D)
        self.queue.extend(chunk.actions[:self.spec.execute_steps])
    return self.adapter.action(self.queue.popleft())       # (D,) → 截断 → 动作字典

# ── ③ VLA 环境：vla/models/serve.py ──
vla = REGISTRY[args.model](); vla.load(args.checkpoint, device="cuda")
listener = Listener(("localhost", args.port))                # 标准库 multiprocessing.connection
while True:
    conn = listener.accept()                                   # 一对一：一次只接一个评测进程
    conn.send_bytes(encode(vla.spec))                          # 握手
    try:
        while True:
            req = decode(conn.recv_bytes())                    # JSON 头 + 数组原始字节
            if req["type"] == "reset": vla.reset(seed=req["seed"]); conn.send_bytes(encode({"ok": True})); continue
            chunk = vla.infer(Observation(**req["obs"]))     ← 模型专属预处理 → 前向 → 后处理
            conn.send_bytes(encode({"actions": chunk.actions}))
    except EOFError:                                           # 评测进程断开，等下一个
        conn.close()

03接口设计

目标可检验的标准
ModularGym 侧代码不 import 任何模型库；VLA 侧代码不 import Genesis / topogym
Scalable加一个 VLA = 1 个子类 + 1 个依赖环境；加一个机器人 = 1 个适配器；加一个任务 = 1 条 instruction
可切换只改评测配置的 policy.address
训练 / 评测一致数据导出与在线评测共用同一个适配器
Simple协议 3 个数据类；不引入插件框架

两层映射：2 + N（已确认）

部署形态：模型与环境怎么分开

三种做法的差别在进程边界放在哪里、谁驱动循环。

Client–Server 的代价。延迟不是主要问题；主要代价是多一个进程要管理。

环节耗时发生频率来源
序列化（JSON 头 + 数组原始字节；3 张 224×224 图 + state，约 0.45 MB）< 1 ms每次推理估算
传输：同机 localhost< 1 ms每次推理估算
传输：同机房 1 GbE约 4 ms每次推理估算（0.45 MB ÷ 125 MB/s）
传输：跨地域（RTT 30 ms）约 40 ms每次推理估算
模型推理（约 3B，单卡）0.1–0.5 s每次推理各模型 README 量级
仿真一个控制步6–10 s每个控制步docs/vla_doc 实测

每次推理之间有 execute_steps（例如 10）个控制步，即 60–100 s 仿真墙钟；通信开销在同机房部署下低于 0.01%。不需要异步推理或 real-time chunking，同步阻塞调用即可。

代价处理
多一个进程要启动和管理run_eval 连接成功并收到 spec 即视为服务就绪；服务日志单独保存
服务崩溃或超时infer 设超时；失败记为 policy_error，不计为任务失败，可重连后重跑该 seed
两侧协议版本不一致PolicySpec 带 protocol_version，握手时校验
跨进程调试不便同一个 BaseVLA 子类可经 LocalClient 在同进程运行（依赖允许时）；服务端可加回放模式，按数据集动作回放来检查 Gym 侧
模型采样有随机性（flow matching 噪声）reset 消息带 seed，服务端设随机种子，保证可复现

传输协议。选 Python 标准库的 TCP 连接（multiprocessing.connection），消息是 JSON 头 + 数组原始字节。TopoGym 环境不需要装任何包。

方案谁在用优点缺点结论
HTTP + JSON（FastAPI）OpenVLA-OFT、X-VLA、MolmoAct2 自带服务简单，curl 可调试数组要 base64 或 JSON 编码，体积和耗时增加；无连接状态，握手和 reset 需额外约定不选
WebSocket + msgpackopenpi、vla-eval、XPolicyLab长连接；二进制数组TopoGym 环境要多装 msgpack、websockets；一对一本机连接用不到它的多客户端与浏览器支持不选
TCP（标准库 multiprocessing.connection）+ JSON 头 + 数组原始字节Python 标准库两侧都不需要装包；自带消息分帧；长连接，连接时下发 PolicySpec编解码自己写（约 30 行）；只用 send_bytes / recv_bytes，不用 pickle（跨环境版本兼容和安全都无法保证）选用
gRPCLeRobot async inference强类型 schema需要 protobuf 代码生成，两侧依赖更重不选
ZMQ REQ/REPIsaac-GR00T 官方服务延迟低无握手 / 健康检查约定不选；GR00T 子类内部可直接调用其策略对象

能否复用 Harbor？Harbor limited 模式属于形态 C。它的价值在于隔离：agent 看不到仿真内部、证据由服务持有、验证在独立沙箱重放。VLA 只能看到适配器给它的输入，不存在这类作弊路径，所以不需要这层隔离。需要的录像功能在 Gym 侧就有，见下节。

标准协议：3 个数据类

# vla/protocol.py —— Gym 与 VLA 两侧共享，只依赖 numpy + 标准库
@dataclass(frozen=True)
class PolicySpec:                    # 服务端在连接建立时发给客户端
    protocol_version: int              # 握手时校验
    name: str                          # "pi05_topogym_cast_coil"
    embodiment: str                    # "aloha" | "panda_robotiq"
    cameras: tuple[str, ...]           # 标准相机名，如 ("cam_high", "cam_left_wrist", "cam_right_wrist")
    image_size: tuple[int, int]        # (H, W)；缩放由 Gym 侧完成，减少传输
    action_space: str                  # "joint_abs" | "ee_abs"
    control_hz: float                  # 训练数据的控制频率
    chunk_size: int                    # 每次推理输出的步数 H
    execute_steps: int                 # 每块执行前几步后重新推理

@dataclass(frozen=True)
class Observation:
    images: dict[str, np.ndarray]      # 相机名 → (H, W, 3) uint8
    state: np.ndarray                  # (D,) float32，排列见下
    instruction: str
    episode_id: str
    step: int

@dataclass(frozen=True)
class ActionChunk:
    actions: np.ndarray                # (H, D) float32，与 state 同一排列，绝对目标

VLA 在 TopoGym 上零样本基本不可用，需要用 TopoGym 自己的演示微调。export_lerobot.py 读取 Env 的 Transition，经同一个 EmbodimentAdapter 转成 LeRobot 数据集；state 排列、夹爪归一化、相机名、图像尺寸、控制频率只在一处定义。导出时同时写关节目标和 TCP 位姿两列（TCP 由 FK 计算），关节空间模型和末端空间模型共用同一批演示。

决策

决策结论原因
VLA 代码位置已定：仓库根 vla/，设计文档在 vla/docs/架构测试禁止 topogym.policies；docs/vla_doc 要求不改 simulator / tasks
控制频率已定：control_decimation = round(400 / 数据频率)，结果记录实际频率（DROID 15 Hz → 27，即 14.81 Hz）与数据频率误差 ≤ 2.6%；不写时间重采样代码
