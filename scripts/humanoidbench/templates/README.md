## Difficulty
The pass mark is a **threshold on the whole episode's return** (`>= {{success_bar}}` over {{max_steps}}
steps), not a predicate on the final state.

{{difficulty}}

**Measured floors** (this instance, `scripts/humanoidbench/gen_tasks.py verify`): an all-zero trajectory
scores **{{nop_return}} / {{success_bar}}**{{nop_note}}. Holding the starting pose instead — the floor a
competent agent gets before writing a controller — scores **{{hold_rate}}** of the bar; that is the number
this task was selected on (the give-away limit of `gen_tasks.py verify`). **External evidence**: published RL
results reach **{{completion_rate}}** of the bar ({{evidence}}) — training runs of millions of environment
steps, not a one-hour coding session, so treat it as proof that the task *has* a solution rather than as a
target.

**The agent does not see the reward function.** It is deleted from the image and restored only inside the
verifier (`images/humanoidbench/scrub_oracles.py`, `tests/rcb_rewards.py`), so the numbers above are
upstream's own scoring (on our physics: see *Physics vs upstream*) while the agent works from the task statement
and the physical state alone.

## GPU
Optional, and passing never depends on it: MuJoCo physics is CPU-only, so a GPU only speeds up the agent's
own offscreen rendering (osmesa ~130 ms/frame, egl ~0.4 ms). Hand one to the agent's container with
`--extra-docker-compose environment/gpu.docker-compose.yaml`; `rcb_hb.py` then picks EGL by itself unless
`MUJOCO_GL` says otherwise. The overlay is not named `docker-compose.yaml` because Harbor would load that on
every machine, and a device reservation the host cannot satisfy stops the container from starting.

## Verification
In its own container, built from `tests/Dockerfile` (no network): the agent's container is gone by then, and only
`/app/output/` crosses over. Open-loop replay of `/app/output/trajectory.npz` from `tests/instance.npz` in a fresh
process, twice; pass iff every replay's episode return reaches `success_bar` **and** the final-state hashes agree
(bit-exact determinism). `tests/grade.py` also writes `/logs/verifier/replay.mp4` and, because Harbor promotes every
`reward.json` key to a leaderboard metric, keeps the per-task numbers (`episode_return`, `success_bar`) in
`/logs/verifier/diagnostics.json`. {{oracle_note}}
