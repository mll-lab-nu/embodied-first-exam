# Cast Keyhole 官方解法核对（2026-09-17）

标准 Hanayama / Huzzle Cast Keyhole 有完整公开解法。进一步核对场景后，当前照片重建网格的
`perpendicular_lower_bore_v1` 初态也已找到完整解：28 段连续碰撞验证通过，原始几何未改。

## 当前实例的新证据

从 `KeyholeAssembly` 实际网格还原金件固定坐标系，银件初态为 `Ry(-90°)`、`[0,47,0] mm`（放大前）。
`baseline_solution.json` 从该初态出发：下部孔道转动 → 顶部沿右侧换向 → 穿过右齿 → 避开下齿 → 退出。
28 段的连续间隙下界均至少 0.15 mm（3 倍场景），终态分离下界 55.5 mm。
两种时间步的完整有界力／力矩台架均通过；最大位置跟踪误差分别 0.00239 / 0.00120 mm，无接触穿透。
双臂耦合 IK 已输出完整 270 帧，另有 971 个关节插值检查点。
随后双臂关节驱动执行完整 23,917 步通过，独立复核了 2,391 个实际状态；
采用预抓取起点、双指接触后辅助抓持，末态两件分离约 55.45 mm 并由双臂保持。

这条路径借鉴官方的转向与槽位对齐思路，但当前初态已经处于下部孔道，**不等于商品出厂初态的 16 图复现**。

## 此前顶部候选与官方图解的对照（历史诊断）

| 检查项 | 目前证据 | 判断 |
| --- | --- | --- |
| 原版谜题能否拆开 | 官网完整图解及实物解题记录 | 有解 |
| 当前网格是否是准确复刻 | 26 × 69 × 3 mm 包络、锐角槽和初态均包含工程推断 | 尚未确认 |
| 现有中段直连能否执行 | 当前证书中点 SAT 重叠 3.675 mm，源文件哈希仍一致 | 该连接不可执行 |
| 是否只差增加搜索时间 | 起始朝向、槽位编号、官方逐图位姿对应尚未标定 | 不能据此判断；应先核对状态定义 |
| 此前顶部候选是否可以录制完整 demo | 该候选完整几何路径未通过 | 不允许跳过失败段录制 |

目前候选固定金件、移动银件；官方图解中的两件动作必须转换为同一个相对坐标系。
若图中两件世界位姿是 `T_gold` 和 `T_silver`，代码需要的银件相对位姿为
`inverse(T_gold) @ T_silver`。图上的左右、上下和顺逆时针不能直接当作固定金件坐标中的轴向。

程序只有 `first_half_turn`、`second_half_turn` 两个显式半圈阶段，但不能据此断言漏了一次翻转：
`transfer_to_second_notch` 的首尾相对姿态还包含绕金件 Z 轴的 180° 变化。
本次计算确认了该变化；旋转轴、旋转中心和中间槽位是否分别对应官方第 4、8、14 图，仍需核对。

当前失败段把银件从 `[11.85, 1.1, 20]` 连接到 `[-12, -20.2, 18]`，
单位是放大前的模板 mm；该目标是工程指定的倒数第二槽，尚未由官方图解逐点配准确认。
终点选错或前置姿态不对应，与正确端点之间存在窄通道，是不同问题，不能混在一起搜索。

此前使用的 [Puzzle Solver Pro 照片教程](https://puzzlesolverpro.com/how-to-solve-the-hanayama-keyhole-brain-teaser-puzzle/)
在 C.3—D.1 要求先到达银件底横梁上方的孔段，再保持高度沿内部转移；不能简化成任意两个槽心的直线插值。
其 D.2 的槽位称呼又需要结合照片确定参考方向。该网页还把设计者写成 Akio Yamamoto，与厂家记录不符；
应只把它作为需交叉核对的照片辅助，不能称作官方教程，也不能把文字槽名直接当作模型坐标。

## 后续实现顺序

1. 以官网 16 幅图为主线，给两件的槽、齿、正反面和开口方向编号，明确每幅图的接触特征。
2. 从官方起点重新建立相对位姿及分动作顺序，特别核对第 7—10 图附近的前置姿态。
   在对应关系建立前，不把现有失败段强行指定为其中某一步。
3. 用未经修改的网格检验这些状态与连接。若官方姿态在模型中不能实现，再定位板厚、槽宽、倒角或轮廓误差；不能为过关直接减小碰撞体。
4. 完整连续几何路径通过后，验证整条动力学和双臂抓持，再录制同步视频。

“68 / 69 段通过”只描述当前候选的局部几何证据，不表示官方解法已完成 98.6%，
也不证明最后一个连接一定存在。当前应优先处理解法状态与模型对应关系，而不是依据搜索失败判定谜题无解。
