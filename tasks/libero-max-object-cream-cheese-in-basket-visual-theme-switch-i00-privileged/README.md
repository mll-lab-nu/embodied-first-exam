## Task
LIBERO-MAX case `pro-visual-noise-glare-object-t01-i07-visual_theme_switch-d0-p195`: a Franka Panda arm at a table, instructed **"Pick the cream cheese and place it in the basket."**, on a LIBERO-PRO variant
of a libero_object task (visual_noise_glare). Online event (visual-theme switch): the first time the gripper comes within
0.18 m of `cream_cheese_1`, LIBERO-MAX changes the scene once (the image colours change (channels permuted (2, 0, 1), scaled (0.7, 1.15, 1.3))). The deliverable is one
replayable trajectory of LIBERO's OSC control steps (`/app/output/trajectory.npz`, `(T, 7)`, T ≤ 280), graded by
LIBERO's success check at its end.

## Difficulty
Privileged mode: every object's pose, the goal, the simulator, unlimited restarts (one simulator per process) and
self-replay. The task itself is short; what makes it harder than LIBERO is the change mid-task, which a plan made at the
start has to survive. This mode is the control for the standard twin, which removes the privileged state.

## Reference solution
162 control steps on this instance (`solution/oracle.npy`), replayed by `solution/solve.sh`: a scripted
controller with privileged state (`scripts/libero-max/reference.py`, not in the image) that re-reads the objects' poses
every step and so follows the change; the event fired at step 10. LIBERO's demonstrations are not in the
image. Re-verified by `scripts/libero-max/freeze.sh`: the replay ends with LIBERO's success at its last step.

## Verification
`tests/grade.py` in a separate sandbox without network: two replays, each in a fresh process, from the verifier's own
copy of the instance (`tests/instance.json`; the rebuilt start is checked against its hash on every load); pass iff both
end in the same state (`deterministic`) and LIBERO's success check holds at the last action (actions after it make the
trajectory invalid). Oracle: the replays end in the live state (hash `a4740eedd406…`) and succeed. `nop`: no trajectory,
reward 0; the instance is not solved at the start.
