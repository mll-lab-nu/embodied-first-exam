## Task
MuJoCo Playground `Go1JoystickFlatTerrain` (Unitree Go1), rebuilt in plain MuJoCo from Playground's scene files: Make the Unitree Go1 follow the joystick command schedule on flat ground for the whole 20 s episode without falling over.
For 20 s the robot gets a joystick command schedule (4 segments: planar velocity and yaw rate in its own frame) and must track it without falling over. The deliverable is one replayable trajectory of joint position targets
(`/app/output/trajectory.npz`, `(T, 12)`, T = 1000 (the whole schedule)).

## Difficulty
Velocity tracking for 20 s: the agent has to make a 12-joint quadruped walk (a gait, not one motion) and steer it through the schedule's changes of speed, direction and turning rate, and an open-loop trajectory of 1000 steps only works if it is computed against the simulator. Torque limits and a soft PD drive leave little margin; Playground trains a neural policy with 200 M steps of PPO for this.

## Reference solution
MuJoCo Playground's own Go1 joystick policy (`experimental/sim2sim/onnx/go1_policy.onnx` @4057c14, not in the image) run closed loop on this instance with the observation of Playground's `play_go1_joystick.py`, its targets recorded (`scripts/mujoco-playground/oracle.py`): worst segment errors 0.073 m/s and 0.091 rad/s. Replayed by `solution/solve.sh` (`solution/oracle.npy`, 1000 rows); the rows are float32-exact, so the
standard twin's client executes the same targets. Re-verified by `scripts/mujoco-playground/select_instances.py`: two
fresh-process replays succeed and end in the same state.

## Verification
`tests/grade.py` in a separate sandbox without network: two replays, each in a fresh process, from the verifier's own
copy of the instance (`tests/instance.json`; the start state is checked against its hash on every load); pass iff both
succeed and end in the same state (`deterministic`). Oracle: success, worst segment errors 0.073 m/s and 0.091 rad/s. `nop`: no trajectory, reward 0.
