## Task
RoboCasa365's `MealPrepStaging` kitchen task with a Franka Panda arm on an Omron mobile base (with a torso lift): Place both pans onto different burners. Then place the corn and the steak on different pans. Produce one replayable trajectory of the robot's native controller commands on one frozen instance; graded on the state after the last action. Generated by `scripts/robocasa365/generate.py`; benchmark notes in `docs/benchmarks/robocasa365.md`.

## Difficulty
Full privileged state, unlimited resets and self-replay; a mobile manipulator in one of RoboCasa365's large, cluttered kitchens, long-horizon contact-rich manipulation with a 20 Hz controller. The standard twin removes the privileged state.

## Reference solution
Retargeted by PR #4 from official demonstration episode 0 (`demo_0`, 1473 recorded actions; RoboCasa365's demonstrations use a different arm controller): it follows the demonstration's recorded arm joint positions as this controller's absolute joint targets, with the base and torso commands corrected by feedback (PR #4 method `demo_feedback`). Executed from the frozen scene by the robot's own controller: 1473 actions in `solution/oracle.npz`. Neither the demonstration nor the reference is in the image; the agent cannot reach them.

## Verification
`tests/grade.py` in a separate sandbox without network: two replays in fresh processes from the verifier's own copy of the instance; `success = deterministic ∧ success on the final state ∧ not solved at the start`. Reference: two fresh-process replays end in the live run's state (hash `8e86941ca8c2…`) and succeed. `nop`: no trajectory, reward 0; the instance is not solved at the start.
