# Pipeline 修复后的场景调整与低难度变体开发注意事项

日期：2026-10-01。适用于调整现有场景以支持可解性，以及新增 `very_easy`、`easier` 等变体的开发工作。

本轮 pipeline 修复主要加强了实例一致性、实际执行记录、评分、录像和恢复。场景几何与难度设计可以继续独立推进；进入 Harbor 验收时，需要让场景、冻结初态、运行镜像、包内工具和判据版本保持一致，并分别验证流程可运行与任务可解。

当前修复候选使用 tooling v5、standard 2.3 和本地运行镜像 0.2.6-cu128。后续场景变更应记录自己的实际版本身份，不直接继承该候选的验证结论。

## 1. 七项主要注意事项

| 注意事项 | 对场景调整和新变体开发的要求 |
| --- | --- |
| 场景和冻结实例一致 | 修改几何、资产、初态或物理配置后，进入 Harbor 验收时使用包含这些改动的镜像，重新冻结实例并生成 privileged / standard 两种任务包。实例不匹配应定位并修正来源，不通过关闭严格检查绕过。旧包、旧镜像身份和历史成功证据保留。 |
| 软体恢复检查更严格 | Blanket、绳索等场景需要核对完整节点状态与资产身份，仅位置或质心相同不足以证明恢复正确。改变拓扑、节点数量或初态后重新准备状态，并验证 reset 和独立进程重建。旧软体实例缺少节点参考且精确状态哈希不匹配时，不能再用质心兜底。 |
| 固定终态判据版本 | 建议新变体先沿用默认 `terminal_contract_version=1`，保持难度比较使用同一规则。B10 子步合同 2 尚未完整验收；Hedgehog、Horseshoe 可显式试验，Slotted Post Ring 的 IPC 后端目前不能使用。更换判据版本应单独记录并重新验证。 |
| 策略依据实际执行量推进 | 被拒绝的动作、终态后的调用不会增加执行记录或物理时间。策略应检查结束状态，使用实际 tick 和模拟时间；40 Hz 下 `dt` 必须是 0.025 s 的整数倍。standard 请求超时后先查询 operation 状态，避免重复执行相同动作。 |
| 流程验证与可解性验证分开 | 先用短动作前缀测试初始化、执行、收尾、回放、评分和输出，再用完整参考策略证明接近、抓取、必要调整及任务完成。检查初态没有直接触发成功，明显错误行为仍能正确判定。短流程通过不证明可解性或长期稳定性。 |
| 复用公共录像和评分 | 正式录制使用共享 `RecordingSession`，时间来自实际物理推进。分别检查评分完成与媒体完整；视频存在不能代替有效成绩，视频时长也不能直接作为模拟时间。避免为新任务另写执行循环、writer 或评分流程。 |
| 新难度接入采样和统计 | 新增具名变体入口不会自动进入现有三档批量采样。若要自动跑五档，需要同步修改采样、任务包命名和结果统计/导出，同时保留旧 seed 与旧变体含义。改任务共用代码时回归原 easy / medium / hard。 |

几何改动还应同步核对公开任务说明、成功目标、禁止接触对象与抓持豁免。例如扩大出口后，需要确认夹爪和抓住的物体可以一起通过，同时保留任务预期的操作要求。场景更简单与判据被放宽应分别记录，避免难度变化来源不清楚。

## 2. 建议采用的开发顺序

1. **本地迭代场景。** 在 `topogym/tasks/`、几何生成器及包内资源中调整结构和初态，先验证可达性、抓持空间及目标是否合理。素材进入包内资源目录并更新登记与哈希。
2. **固定待验收版本。** 场景稳定后，记录源码、资产、seed、物理配置及判据版本，构建对应镜像，冻结实例，再生成两个模式的新任务包。已冻结包采用新身份交付，避免原地替换历史证据。
3. **执行快速全流程检查。** 不调用模型，执行少量合法动作或 hold，通过正常结束机制完成评分和录像收尾。privileged 覆盖提交及两遍评分回放；standard 覆盖 live、服务退出、独立进程 replay 和 verifier。预期未解题的短前缀可以得到 0 分，只要分类正确且流程完整。
4. **补完整可解性与判据验证。** 运行完整机器人参考策略，确认成功；同时检查明确失败或违规案例，防止简化后的场景在初态或无关动作下误报成功。保存与该版本对应的轨迹、实际 tick、评分及共享录像。
5. **验证旧变体并接入批量评测。** 根据共用代码的影响范围回归旧变体，再扩展采样和统计。结果中区分流程通过、完整求解通过、未验证及基础设施故障。

快速全流程检查仍保留真实物理、正式评分与输出步骤，主要通过减少动作长度、取消模型求解来节省时间。初始化与重建成本仍然存在；这是一项建议的验收方式，不表示完整快速矩阵工具或所有矩阵测试已经完成。

Blanket 的准备过程另有编号 attempt 和完整性指针：准备失败时保留残留与日志，通过新 attempt 恢复；已经被冻结包引用的完整准备资产不覆盖。跨版本运行使用新的 run 身份，避免把旧 journal 直接交给新协议恢复。

## 3. 当前两档变体计划的适用范围

当前计划为 Hedgehog、Horseshoe、Slotted Post Ring 各新增 `very_easy` 和 `easier`，共六个新变体，保留原 easy / medium / hard。

按原计划每个任务难度固定一个 sample、每个 sample 覆盖两种模式计算：

- 原矩阵：13 个任务 × 3 档 × 2 模式 = 78 项。
- 新增覆盖：3 个任务 × 2 档 × 2 模式 = 12 项。
- 纳入这六个新变体后：共 90 项。增加 seed 或 sample 数量时，矩阵相应扩大。

建议先让新增 12 项通过快速全流程检查，再逐变体补完整可解性证据。`very_easy < easier < easy` 是设计目标，需要通过实际操作要求和运行结果确认。

## 4. 共享代码边界与尚未完成的验收

任务专属几何、素材和变体参数可独立修改。共享 simulator、World、`topogym/tasks/base.py`、公共判据、Harbor 模板和生成器涉及多任务行为，修改前应核对其他成员正在进行的工作，并按实际影响范围补回归。

本轮修复仍缺少 B10 真实瞬时违规对照、完整 78 项矩阵、软体恢复的完整资格、真实 GPU 卡死恢复及性能专项验收。新变体不能自动继承这些尚未取得的资格；尤其不能把短程回放成功外推为跨 GPU 兼容、长期显存稳定或完整可解性。
